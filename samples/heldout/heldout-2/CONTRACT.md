# 見ていない様式の書き手への頼み（正解の形 moyai.heldout.truth/0）

MOYAI は、保全の資料（機器台帳・星取表・作業日報・工事報告書・点検表の写真）を読み、設備の計画に組み立てるアプリです。
この頼みは、MOYAI の読み手が**一度も見たことのない書き方**の資料を作ってもらうためのものです。あなたが作った資料で、凍結した読み手がどこまで読めるかを測ります。

## 守ってほしいこと

- あなたが見てよいのは、作業のフォルダに置いた `world.json`（正解の世界）と、この文書だけです。
- MOYAI のリポジトリ（`C:\Users\kazuh\Moyai` と、その写しの `C:\tmp\moyai-*`）の中は、文書も含めて読まないでください。
  - 開発用の資料の書き方を知ると、それに似た書き方になり、「見ていない様式」でなくなるためです。
  - 読まないことは仕組みでは止められません。証拠は、時刻の順とハッシュだけです。
- 資料はすべて架空です。どのファイルにも「【架空】」を入れてください。
  - Excel：題のセルと、ファイルの作成者の欄。
  - CSV：1 行目の題。
  - PDF：題の文字。
  - 写真：写した紙の題。
- 実在の自治体名・施設名・会社名・人名は使わないでください。

## 作るもの

作業のフォルダ（例 `C:\tmp\moyai-heldout-2\`）の下に、次を置きます。

```
world.json          渡したもの（変えない）
CONTRACT.md         この文書（変えない）
files/              資料
truth.json          正解（下の形）
writer/             資料を書いたコード（Python 3.12。openpyxl・Pillow・pypdfium2 と、LibreOffice の headless が使える）
writer/check.py     正解と資料が食い違っていないかを、あなたが確かめるコード
WRITER.md           どんな書き方にしたか・なぜか・現場のどんな資料を思い浮かべたか・乱数の種
```

コードはもう一度走らせると同じファイルを書くようにしてください（乱数の種と「今日」を固定する）。

### 資料（それぞれ 1 つ以上）

| 種類（kind） | 形式（format） | 中身 |
|---|---|---|
| `ledger` 機器台帳 | xlsx | 世界のすべての機器。設備のまとまり（`path`）・名前・番号（`tag`）・設置年・仕様 |
| `star` 星取表 | xlsx | 機器 × 年度の表。世界の作業の、予定と実績の印 |
| `daily` 作業の記録 | csv | 作業ごとか日ごとの行。日付・機器・作業・工数 |
| `report` 工事報告書 | pdf（文字のある PDF） | 1 回の工事（例：ある年度の、ある号炉の定期整備）の報告。行ごとに機器・作業・工期・日数・工数 |
| `photo` 点検表などの写真 | jpg | 紙の帳票を撮った写真（傾き・影・ぼけ・手書きの印など） |

- 書き方は、あなたが現場にありそうだと思うものを選んでください。開発用の資料に似せる必要はありません（見ていないので、似せられません）。
- 自治体・委託先・メーカーの資料には、次のような揺れがあります。自分で考えて混ぜてください。
  - 見出しの段数、年度の書き方（和暦・西暦・年号の切り替え）、結合したセル。
  - 番号の振り方、名前と番号の並べ方、「〃」や空欄の省略、半角カナ、全角と半角。
  - 凡例と注記、小計と合計、1 シートに複数の表、文字コード（Shift_JIS／UTF-8）、日付と工数の書き方。
- ただし、**人が読めば 1 通りに決まる**資料にしてください。人が読んでも決まらない書き方（意味の分からない記号を凡例無しで使うなど）は、作るなら WRITER.md に「わざと決まらなくした」と書いてください。
- 値は `world.json` と食い違わないようにしてください（日付・工数・日数・設置年・機器の組）。
  - 書かない値は書かなくてかまいません。
  - 工数を時間で書くなら、`man_day_hours` 時間で 1 人・日です。
- 星取表の 1 つのセルは、予定か実績のどちらか 1 つを表すようにしてください（1 つのセルで両方を表す記号は使わない）。
- 写真の中身は測りません（AI が読むので、別の回で測ります）。何を撮ったかだけを書きます。

## 正解の形（`truth.json`）

```json
{
  "schema": "moyai.heldout.truth/0",
  "set": "heldout-2",
  "world": "world.json",
  "files": [ … ],
  "assets": [ … ],
  "marks": [ … ],
  "events": [ … ]
}
```

### 場所（`at`）：資料のどこにあるか

次の 3 つのどれかで書きます。

| 書き方 | 意味 | 使う所 |
|---|---|---|
| `{"cell": "C12", "sheet": "台帳"}` | そのセル | xlsx・csv |
| `{"row": 15, "sheet": null}` | その行のすべてのセル | xlsx・csv |
| `{"texts": ["3", "誘引通風機", "2023/04/10"]}` | それぞれの文字を持つセルがそろう、ただ 1 つの行 | pdf（xlsx・csv でも使える） |

- **xlsx**：`sheet` はシートの名前です。省くと最初のシートになります。セルは A1 の形で、結合したセルは範囲の左上です。
- **csv**：`sheet` は null か省きます。列は A, B, C… です。行の番号は、ファイルの物理の行の番号（1 から。題や空の行も数える）です。
  - 囲みの中で改行した記録は、記録の始まりの行の番号になります。
- **pdf**：読み手は、文字の位置から表の格子を組み直します。行の番号もセルの位置も読み手が決めるので、`texts` を使ってください。
  - その行に見えている文字（1 つのセルや 1 つの文字の並びに入っているもの）を 2〜4 個選び、合わせてその資料の中で 1 行にしか当たらない組にします。例：No. と機器の名前と開始日。
  - 文字は、空白を除き、全角と半角をそろえて（NFKC）比べます。完全に同じセルが無ければ、その文字を含むセルでもかまいません。
  - 頁ごとにくり返す見出しの文字は、選ばないでください。

### `files`：資料ごとに 1 つ

```json
{ "file": "daily/sagyo-kiroku.csv", "format": "csv", "kind": "daily", "encoding": "cp932", "delimiter": ",",
  "note": "どんな書き方か（1〜3 文）" }
```

- `file`：`files/` からの相対の道（`/` で区切る）。
- `encoding`・`delimiter`：csv のときだけです。`encoding` は Python の codec の名前（`cp932`・`utf-8`・`utf-8-sig` など）、`delimiter` は `,` か `\t` です。
- `source_xlsx`：pdf を xlsx から書き出したなら、その xlsx（`files/` に置き、`files` には載せない）。
- `hidden_data`：隠した行・列・シートにある中身を、計画に入れるべきか（`"include"`／`"exclude"`）。隠したものが無ければ省きます。
- `photo_of`：写真のとき、何を撮ったか。例：`{"file": "reports/houkoku-2023-1.pdf", "page": 1}`。

### `assets`：機器台帳と星取表の、まとまり・機器・部位のセル

```json
{ "file": "daicho.xlsx", "at": {"cell": "B7", "sheet": "機器台帳"}, "kind": "equipment", "level": 3,
  "parent": {"cell": "B5", "sheet": "機器台帳"}, "equipment_id": "E04",
  "name_text": "ストーカ（STK-1）", "name": "ストーカ", "tag": "STK-1", "install_year": 2002,
  "spec_texts": ["処理能力 100 t/日"] }
```

- `kind`：`group`（設備・系統などのまとまり）、`equipment`（世界の `equipment` の 1 つ）、`part`（機器の部位）。
- `at`：名前を書いたセル。
- `level`：その資料の中の段（1 から）。段が無い書き方なら null。
- `parent`：親の名前のセル。根なら null。星取表のように、親が「縦に結合したまとまりのセル」なら、結合の左上のセルです。
- `equipment_id`：`equipment` と `part` のときに書きます。`group` は null です。
- `path`：`group` のときだけ書きます。世界の `equipment[].path` の、その段までの名前です（書いた文字ではなく、同じものかを決める鍵）。
  - 例：「受入供給設備」のまとまりなら `["受入供給設備"]`。
- `name_text`：セルに書いた文字そのものです（改行もそのまま）。
- `name`・`tag`：その資料での呼び名と、番号です。番号を書いていなければ `tag` は null です。
- `install_year`：その行に設置年を書いたなら、世界の値です。
- `spec_texts`：その機器の仕様・備考として書いた**セルの文字そのもの**です（1 セル 1 つ）。
- 機器台帳のすべての機器とまとまり、星取表の機器の行は、すべて書いてください。
  - 星取表のまとまりのセルは、書くなら `"measure": false` を付けてください（引き当てだけに使います）。

### `marks`：星取表の、作業を表す印のセル

```json
{ "file": "hoshitori.xlsx", "at": {"cell": "K9", "sheet": "保全計画"}, "fiscal_year": 2023, "status": "actual",
  "equipment_id": "E04", "work_ids": ["W0101"], "symbol": "●" }
```

- 予定か実績を表す、すべての印のセルを書きます（凡例の中の見本の記号は除く）。
- 1 つの印が、いくつかの作業を指すなら（例：同じ年度の点検と精密機能検査）、`work_ids` に並べます。
- 凡例に無い記号や、凡例と違う意味の記号を使ったら、その印の本当の意味を `status` に書きます。

### `events`：作業の記録と工事報告書の、作業の行

```json
{ "file": "daily/sagyo-kiroku.csv", "at": {"row": 12}, "status": "actual", "fiscal_year": 2022,
  "equipment_ids": ["E04"], "work_ids": ["W0063"], "start": "2022-04-06", "end": "2022-04-06",
  "man_days": 3, "days": null, "bundle": false }
```

- 作業を表すすべての行を書きます。題・見出し・合計・注記の行は書きません。
- `start`・`end`：その行が表す期間です。1 日の記録なら同じ日です。
- `man_days`：その行に書いた工数を、人・日に直した値です。書いていなければ null です。
- `days`：その行に書いた日数（工期）です。書いていなければ null です。
- `bundle`：いくつかの機器をまとめた 1 行（「一式」など）なら true です。
  - そのときの `equipment_ids` はまとめた機器のすべてで、`man_days` はその行に書いた工数（まとめた全体）です。
- 1 つの作業を何日にも分けて書くなら、行ごとに書きます。その行の工数を、それぞれの行に書きます。

## 確かめ（`writer/check.py`）

次を確かめてから、終わりにしてください。

1. `truth.json` が上の形です（知らないキーを入れない）。
2. ID が `world.json` にあります。
3. xlsx と csv の `cell` の場所には、`assets` なら `name_text` と同じ文字、`marks` なら `symbol` と同じ文字があります。
4. `row` の場所に、中身があります。
5. `texts` は、pdf なら pypdfium2 で取り出した頁の文字に、それぞれの文字があります。
   - 元の xlsx があるなら、その xlsx の 1 行だけにそろって当たることも確かめます。
6. 日付・工数・日数・設置年が、`world.json` と食い違いません。

## 終わったら

作業のフォルダの中身は、そのまま置いておいてください（あとでハッシュを取り、公開します）。

返事には次を書いてください。資料の中身は書かないでください。

- 作った資料の一覧（形式・種類・行の数）。
- 書き方の要点。
- `check.py` の結果。
- 確かめられなかったこと。
