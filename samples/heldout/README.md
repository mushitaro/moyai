# 見ていない様式（import.heldout）

`docs/plan.md` §2.6 の試験です。開発用の資料に合わせた読み手が、見たことのない書き方の資料をどこまで読めるかを、測った値のまま出します。

## 順番（時刻の順で示す）

1. **読み手を凍結する。** 開発用の Excel・CSV・PDF で ① 0・② 0・③ 100% に届いたら、`src/` と `packs/` の commit にタグを打ちます。
   - 1 回目のタグは `reader-freeze-1` です。
   - 測る道具（`tests/heldout/`・`scripts/heldout/`）も、このタグに入れます。
2. **新しい書き手が資料を書く。** 書くのは、生成器（`samples/factory/`）もリポジトリも見ない、新しいサブエージェントです。
   - 渡すのは 2 つだけです。正解の世界の書き出し（`scripts/heldout/export-world.mjs`。生成器の書き方の決まりは含まない）と、正解の形の説明（`CONTRACT.md`）。
   - 書き手は、リポジトリの外の作業のフォルダに、資料・正解・書いたコードを置きます。
3. **ハッシュだけを先にコミットする。** 組のハッシュ（`scripts/heldout/hash.mjs`）を `hashes/<組>.json` にコミットして push します。
   - 組のハッシュは、`measured/` を除くファイルの SHA-256 を道の順に並べた一覧の SHA-256 です。
   - このとき、中身はまだ公開しません。
4. **凍結した読み手で測る。** タグを worktree に取り出し、その中で測ります。主線の開発は続けてかまいません。
   - 測る前に、別の読み手で原本の事実を取ります（`scripts/heldout/facts.py`）。
   - `MOYAI_HELDOUT_DIR=<組> MOYAI_HELDOUT_OUT=<組>/measured/result.json npx vitest run tests/heldout/heldout.test.ts` で測ります。
   - 結果には、測った読み手の commit と、`src/`・`packs/` の木のハッシュを書きます。
5. **中身と結果を公開する。** 組のフォルダ（書き手のコード・資料・正解・`measured/`）を `samples/heldout/<組>/` にコミットします。
   - 試験（`tests/heldout/heldout.test.ts`）が次を確かめます。
     - タグ → ハッシュ → 公開の順になっている。
     - タグの木に組の中身が無い。
     - 公開した中身のハッシュが先にコミットしたハッシュと同じ。
     - 測った読み手の `src/` と `packs/` が、タグと同じ木である。

届かなければ、測った値のまま書きます。直してよいのは、一般の手がかりと一般の質問の形だけです。直したら、新しい見ていない様式（`reader-freeze-2`）で測り直します。同じファイルで測り直すと、その様式に合わせた直しになるためです。

## 測るもの

物差しの番号は、`docs/plan.md` §2.6 と同じです。

- ① 原本の漏れ：別の読み手の事実と比べます。
  - xlsx は openpyxl、CSV は Python の csv です。
  - PDF は、元にした xlsx があれば、その xlsx と比べます。
- ② 未解決のセル。
- ③ 読み取りの正しさ：機器の節・印・作業の行が、正解と合うかを見ます。
- ⑤ 聞いた数。
- ⑥ 取り戻せた割合。

質問には、正解から答える決まった台本（`tests/heldout/harness.ts`）が人の代わりに答えます。作者は「人」、理由は「試験の台本が押した（正解の世界から）」と記録します。正解から答えられない質問は、開いたまま（未解決）に数えます。

写真は、この台本では読みません（AI が読みます）。写真は、別の回（AI を入れた 1 回）で測ります。

## 道具が正しいことの確かめ

正解の形は、書き方に依らない形です（`tests/heldout/contract.ts`）。`tests/heldout/calibrate.test.ts` が、開発用の工場の正解をこの形に写して、次を確かめます。

- この道具の台本が、開発用の台本と同じ数の質問に、同じだけ答える。
- 開発用の資料で、開発用の物差しと同じ数（①・②・③・⑥）を出す。
- 計画をわざと壊したとき、台帳と星取表は同じ数だけ落とす。日報と報告書は、同じか多く落とす。この道具は、日報の行でも年度と予定・実績を見るためです。

見ていない様式で数が落ちたとき、道具の誤りではなく、読み手の数だと言えるようにするためです。

## 保証できないこと

- 書き手のサブエージェントがリポジトリを読まなかったことは、仕組みでは止めきれません。
  - 証拠は 2 つです。時刻の順（タグ → ハッシュのコミット → 公開）と、ハッシュの一致です。
  - 書き手に渡した頼み（`CONTRACT.md`）と、書き手の返事は、組のフォルダに残します。
- 正解は書き手が書いたものです。正解の誤りは、読み手の誤りに数えられます。
  - 書き手は `writer/check.py` で、正解と資料の食い違いを確かめています。
  - 測ったあとに見つけた正解の誤りは、直さずに、結果と一緒に書きます。
