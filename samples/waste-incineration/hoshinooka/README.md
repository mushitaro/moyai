# 【架空】ほしの丘リサイクルセンター（架空中央広域環境組合）— サンプルの世界

すべて架空の施設です。実在の自治体・施設・会社・人とは関係ありません。施設の性質の分布だけを、公開の統計から加工して使いました（下の「出典と加工」）。

この README は作る側と測る人のためのものです。読み手（AI）には渡しません。読み手の質問に答える役が見るのは `user.md` と `answer/world.json` だけです。

## わざと入れた揺れと食い違い

### 1. 資料の汚さ（取り込みが読み切るもの）

- `【架空】ほしの丘RC_保全計画_R1-R13.xlsx`：大分類の列を縦に結合し、機器・号炉・部位を列に分けた。上と同じ名前は「〃」や空欄。年度の見出しは元号を 1 段にまとめ（「平　成」「令　和」）、その下に年の数（元・2・3…）。凡例：年度ごとに「予定」と「実績」の 2 列。予定の欄の ○ は当初の計画、実績の欄の ● はやった年、△ は一部だけ。周期を「2年」と文字で書いた行が混ざる（数の行と文字の行）。号炉の書き方が機器ごとに揺れる（#1・１号炉）。1 台ずつの行と、2 炉で 1 行・台数をまとめて 1 行の機器が混ざる。Excel のメモ：延期の理由（「R2予定 → R3に延期」）、計画外の臨時の実施、完成図書との名前の違い。備考に取替・新設・更新（「R3 更新」）と、文の中の年度（「R18に更新の予定」）、事後の補修（「R5.3.8 …（臨時）」）。自分の作業を持つ親の行（保全計画 の 22 行「受入・供給設備 › ゴミクレーン › 1号機」に「年次自主検査」、その下に子の行。ほかに 12 行）。未来の年度の列を網掛けで分けた。

## 正解の形

- `answer/files/<stem>.json`：ファイルごとの正解（作り手への指示書 §5.1）。Excel は `sheet` と `r`、CSV は `r`（1 行目が 1）、PDF は `seq`、写真は `seq` と `image`。
- 星取表の `path` は名前の頭の番号（「1.」「(1)」「■」）と字下げの空白・「・」を外した名前の並び。「〃」の行は意味の名前で書いた。`code` は機器番号の列があるときだけ。
- 予定と実績を 2 列に分けた星取表は、実績の列を `marks`、予定の列を `plans` に入れた。3 年度にまたがる結合のセル（基幹改良）は、結合が掛かる年度すべてに同じ文字を入れた。
- 写真の正解で、影やぼけで読めなくしたセルは「読めない」。
- `answer/world.json`：機器（1 台ずつ）・作業（属性・日付・工数・業者・契約）・契約・結び（`links`：どの資料のどの行がどの作業か）・書いていない作業と理由・計画の欠け・書き漏れ・施設の性質。
- `gen/evidence/<stem>.json`：正解の値が書いてあるセルの番地と値（`check.py` が照らす）。

## 出典と加工

- 施設の性質（炉型・処理能力の帯・蒸気タービン・灰処理・運営の形）は、環境省「一般廃棄物処理実態調査結果（令和 6 年度）施設の表（焼却施設）」から数だけを取り出した `packs/waste-incineration/national/table.json` の分布に寄せて選んだ（加工した）。表の行や施設名は写していない。
- 機器の項目は、環境省の長寿命化総合計画作成の手引きの表Ⅱ-4（パックの `common.json`）。法令の点検の周期は、照らしたもの（精密機能検査の 3 年＝課長通知）だけを `recommendation` にし、ほかは `app`（`world.json` の legal）。
- 金額・工数・業者・型式・製造番号・人名はすべて架空。
