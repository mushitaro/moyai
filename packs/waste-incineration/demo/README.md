# デモの資料（ごみ焼却施設の Skillパック）

ここの資料は、どれも架空。中に【架空】と書いてある。サンプルを作る道具（`samples/factory/`）が作った `samples/out/waste-incineration/fictional-1/` の 3 つを写した。実在の施設・事業者・人ではない。

| 資料 | 中身 |
|---|---|
| `equipment-ledger.xlsx` | 施設台帳（設備 › 機器 › 部位） |
| `plan-hoshitori.xlsx` | 保全の計画の星取表 |
| `daily-report.csv` | 作業日報の書き出し（Shift_JIS） |

`demo.json` はデモの施設名。作業画面の施設名が空のときだけ使う。

## チャットでのデモの進め方

MOYAI のツールが無いとき（MCP がつながっていない）は、デモの前に `skills/moyai/SKILL.md` の入れる手順を Claude がする。setup は中身をチャットで見せ、「はい」をもらったら `--yes` を付けて Claude が走らせる。利用者に端末・Ctrl+C・ダブルクリックを頼まない。Claude Desktop に入れたときだけ、Desktop の開き直しを 1 回頼む。

デモは、利用者が作業画面で動きを見るためにある。Claude だけで最後まで進めて結果を話すのは、デモではない。利用者に端末・ダウンロード・ドラッグを頼まない。

決まり：
- 1 回の返事で進めるのは 1 段だけ。ツールを呼んだら止まり、「画面の〇〇に△△が出ました」と 2 行までで言い、「次へ進めてよいですか」と聞いて待つ。
- 利用者が「次」「はい」と言うまで、次の段のツールを呼ばない。
- 説明は短く。数字は画面に出ているものを言う。

段：
1. 作業画面を先に開く。`intake_survey` を呼ぶと中継が橋渡しを起こし、結果の `workScreenUrl`（既定 http://127.0.0.1:43110/）が返る。シェルがあれば Claude が開き、無ければ利用者にリンクを開いてもらう。「画面が出たら教えてください」と聞いて待つ。
2. `intake_add_files`（source: demo）で、ここの 3 つの資料を作業画面に入れる。Skillパックと施設名が空なら、このデモのものになる。画面の左に 3 つの資料が並んだかを聞いて待つ。
3. `intake_survey` で要約と質問を読み、画面に出ている質問の数を言う。
4. 質問を 1 つずつ聞く。選択肢と既定の答えを見せ、答えを `intake_settle` で置く（作者は ai_relayed_human、理由を添える）。置くたびに、画面の質問が 1 つ減ったことを言って待つ。
5. `intake_compose` で計画を作り、「HOSHITORI の星取表を見てください」と言って待つ。
6. `chart_rows` で行を読み、見どころを 1 つだけ話す（画面のどの行か）。
7. 確定は人が画面でする。Claude は確定しない。「確定のシートで受けて、署名して確定してください」と言って待つ。

デモの計画も架空。確定した版は保存先に残る。消すときは、アンインストールで保存先も消すかを利用者に聞く。

作業画面に架空でない資料か、ほかの Skillパックの資料が入っていれば、デモの資料は入れない（混ぜない）。そのときは今の作業を残すかを利用者に聞き、要らなければ作業画面を読み込み直してもらう（確定していない作業は消える）。
