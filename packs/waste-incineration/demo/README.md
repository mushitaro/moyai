## チャットでのデモの進め方

MOYAI のツールが無いとき（MCP がつながっていない）は、デモの前に `skills/moyai/SKILL.md` の入れる手順を Claude がする。setup は中身をチャットで見せ、「はい」をもらったら `--yes` を付けて Claude が走らせる。利用者に端末・Ctrl+C・ダブルクリックを頼まない。Claude Desktop に入れたときだけ、Desktop の開き直しを 1 回頼む。

デモは、利用者が作業画面で動きを見るためにある。Claude だけで最後まで進めて結果を話すのは、デモではない。利用者に端末・ダウンロード・ドラッグを頼まない。

決まり：
- 1 回の返事で進めるのは 1 段だけ。ツールを呼んだら止まり、「画面の〇〇に△△が出ました」と 2 行までで言い、「次へ進めてよいですか」と聞いて待つ。
- 利用者が「次」「はい」と言うまで、次の段のツールを呼ばない。
- 説明は短く。数字は画面に出ているものを言う。

段：
1. 作業画面を先に開く。`intake_survey` を呼ぶと中継が橋渡しを起こし、結果の `workScreenUrl`（既定 http://127.0.0.1:43110/）が返る。シェルがあれば Claude が開き、無ければ利用者にリンクを開いてもらう。「画面が出たら教えてください」と聞いて待つ。
2. `intake_add_files`（source: demo）で、ここの 3 つの資料を作業画面に入れる。Skillパックと施設名が空なら、このデモのものになる。画面の左に 3 つの資料が並んだかを聞いて待つ。
3. `intake_survey` で要約と質問を読み、画面に出ている質問の数を言う。
4. 質問を 1 つずつ聞く。選択肢と既定の答えを見せ（既定の答えの無い質問、たとえば「○済」が計画か実績か・CSV の金額の単位は、選択肢だけを見せて利用者に選んでもらう）、答えを `intake_settle` で置く（作者は ai_relayed_human、理由を添える）。置くたびに、画面の質問が 1 つ減ったことを言って待つ。
5. `intake_compose` で計画を作り、「HOSHITORI の星取表を見てください」と言って待つ。
6. `chart_rows` で行を読み、見どころを 1 つだけ話す（画面のどの行か）。
7. 確定は人が画面でする。Claude は確定しない。「確定のシートで受けて、署名して確定してください」と言って待つ。

## 日報と発注台帳を読み切る（カスタムスキルの例）

作業日報（清書）と財務会計の CSV は、標準の読み方に合わない。日報は表ではなく帳票（日ごとに 1 シート。項目と値の欄と、「作業内容」の下の文の行）で、標準の読み方では見出しの欄（「日　付」「天　候」「作業責任者」…）が機器の節になり、作業は 0。CSV は見出しが財務会計の語（「件名」「債権者名」「金額」「起票日」）で、標準の読み方では「節名称」（委託料・需用費…）が機器の名前になり、2 つ目の塊（＜支出命令＞）は見出しをくり返すので、データの 1 行目が見出しになる。

資料を落とさず、1 段目の Skill の「Read every file」のとおり、会話で 3 段目の規則（施設の読み方）を作って読む。読み切れる規則の例（`reading_rules_propose` の rules。id・text・author・reason は省いた）：

```json
[
  { "kind": "form", "title": "作業日報",
    "fields": [ { "label": "日付", "role": "date" }, { "label": "作業箇所", "role": "unit" }, { "label": "計", "role": "effort", "column": "工数（人日）" } ],
    "lines": { "label": "作業内容", "split": "assetWork" } },
  { "kind": "headerRow", "row": 22, "when": { "file": "*財務会計CSV.csv" } },
  { "kind": "contractColumn", "column": "件名", "field": "title" },
  { "kind": "contractColumn", "column": "債権者名", "field": "vendor" },
  { "kind": "contractColumn", "column": "起票日", "field": "orderDate" },
  { "kind": "contractColumn", "column": "金額", "field": "orderAmount" },
  { "kind": "contractColumn", "column": "支払予定日", "field": "payDate" },
  { "kind": "contractColumn", "column": "伝票区分", "field": "category" }
]
```

測った数（2026-11-25、手元の Linux、取り込みのセッションに直に入れた。試験 `tests/unit/import/form-rule.test.ts`）：
- 日報だけ：規則なしは作業 0・見出しの欄の機器の節 376。規則ありは作業の行 76（日付・号炉・機器・作業。作業の行が 1 つの日はその日の工数も）・見出しの欄の機器 0。曜日が日付と合わない 1 枚（6.19「令和7年6月19日（水）」）だけ日付が読めず、問いに残る。その日の作業の行が 2 つ以上の日は、その日の工数を行に割らない（理由を付けて外す）。
- CSV だけ：規則なしは「委託料」などが機器の名前になる。規則ありは 2 つの塊の 20 行がどれも契約の記録になり、未解決のセル 0・問い 0（金額の単位の問いに円と答えたあと）。
- 3 つを一緒に（どの問いにも答えたあと。選べるのが「外す」だけの問い 2 つ〔曜日の食い違う日付・計画の意味の決まらないセル 1〕は外すと答えた）：計画の作業 169 → 244、作業の明細 554 → 629、機器の節 530 → 496。日報の作業の行 76 のうち 22 行は星取表の機器と同じ名前で結ばれ、54 行の機器の名前は「新しい機器として入れるか」を聞かれる（同じ機器の呼び名は sameAsset の規則で足していく）。
- 支出命令の塊の「金額」も契約の金額（orderAmount）として読む（同じ見出しの 2 つの塊を、列の名前の規則では分けられない）。

デモの通し（`tests/demo/walkthrough-flow.ts`）と架空の Maximo の中身は、今は規則なしの読み方に合わせてある（この節の規則は、デモの通しには入れていない）。

## 連携のデモ（架空の Maximo）

「Maximo との連携のデモをして」と頼まれたとき（デモの続きに連携を足すときも）。架空の Maximo は橋渡しのメモリの中だけにあり、どこにも通信しない（行き先は予約のオリジン `https://demo-maximo.moyai.invalid`。API キーは無い）。本物のつなぎ先と API キーを足すのは、今までどおり人だけ。

段（1 回の返事で 1 段。上の決まりと同じ）：
1. `connect_demo` を呼ぶ。設定の「連携」がオフなら断られるので、利用者に「設定の連携をオンにしてください」と 1 行で頼み（オンにするのは人だけ）、オンになったら呼び直す。架空の Maximo がテスト環境のつなぎ先として 1 つ足される。
2. 空の作業画面に `intake_add_files`（source: demo）でデモの資料を入れ、`connect_read`（target は connect_demo が返した ID）で、架空の Maximo の作業の実績を資料として 1 つ足す。利用者の資料のある作業画面には入れない（refused: mixed）。
3. 質問・計画・星取表は上の段と同じ。人が確定・署名する。
4. `connect_plan` で、連携のシートに突合（一致・片方だけ・食い違い）と書き込みの差分（足す・変える。消さない）が出る。画面の数を言う。
5. 人が連携のシートで「送る」を押す（テスト環境なので鍵は要らない）。架空の Maximo に書かれ、`connect_plan` をもう一度呼ぶと差分が 0 になる。

架空の Maximo は、MOYAI を起こし直すと消える（もう一度 `connect_demo`。`reset: true` で初めの中身に戻す）。

上の「デモ」の段（`tests/demo/walkthrough-flow.ts`）には連携の段を足していない。チャットのデモを短く保つため（連携は頼まれたときだけ）で、連携のデモの通しは `tests/e2e/connect-demo.spec.ts` が確かめる。

デモの計画も架空。確定した版は保存先に残る。消すときは、アンインストールで保存先も消すかを利用者に聞く。

作業画面に架空でない資料か、ほかの Skillパックの資料が入っていれば、デモの資料は入れない（混ぜない）。そのときは今の作業を残すかを利用者に聞き、要らなければ作業画面を読み込み直してもらう（確定していない作業は消える）。
