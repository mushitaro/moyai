# デモの資料（ごみ焼却施設の Skillパック）

ここの資料は、どれも架空。中に【架空】と書いてある。サンプルを作る道具（`samples/factory/`）が作った `samples/out/waste-incineration/fictional-1/` の 3 つを写した。実在の施設・事業者・人ではない。

| 資料 | 中身 |
|---|---|
| `equipment-ledger.xlsx` | 施設台帳（設備 › 機器 › 部位） |
| `plan-hoshitori.xlsx` | 保全の計画の星取表 |
| `daily-report.csv` | 作業日報の書き出し（Shift_JIS） |

`demo.json` はデモの施設名。作業画面の施設名が空のときだけ使う。

## チャットでのデモの進め方

利用者が「デモして」と言ったら、Claude は次の順に進める。利用者に端末・ダウンロード・ドラッグを頼まない。

1. `intake_add_files`（source: demo）で、ここの 3 つの資料を作業画面に入れる。Skillパックと施設名が空なら、このデモのものになる。結果は資料の名前・大きさ・件数だけで、中身は返らない。
2. 作業画面が開いていなければ、結果の `workScreenUrl` を開く（シェルがあれば Claude が開く。無ければ利用者にリンクを開いてもらう）。
3. `intake_survey` で要約と質問を読む。
4. 質問を利用者に聞く。選択肢と既定の答えを見せ、答えを `intake_settle` で置く（作者は ai_relayed_human、理由を添える）。質問が無くなるまで 3 と 4 を繰り返す。
5. `intake_compose` で計画を作り始め、`intake_survey`（part: compose）で結果を読む。
6. `chart_rows` で星取表の行を読み、利用者に見どころを話す。
7. 確定は人が画面でする。Claude は確定しない。利用者に HOSHITORI の確定のシートを見てもらう。

デモの計画も架空。確定した版は保存先に残る。消すときは、アンインストールで保存先も消すかを利用者に聞く。

作業画面に架空でない資料か、ほかの Skillパックの資料が入っていれば、デモの資料は入れない（混ぜない）。そのときは今の作業を残すかを利用者に聞き、要らなければ作業画面を読み込み直してもらう（確定していない作業は消える）。
