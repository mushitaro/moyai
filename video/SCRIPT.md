# 3 分の動画の台本（v0 の下書き、2026-11-04）

- 元は運営者の動画の計画（S0〜S7）。ここでは、今の実装に合わせて場面ごとの画・語り・画面の文言・撮る素材を決める。
- 長さは 2:57。語りは運営者の声で日本語。英語字幕を焼き込む。どの場面にも右下にビルドの印を置く。
- 数字は描くときにリポジトリから数える。下の「○」は数えて埋める所。
- 【要決定】は運営者が決める所。

- 語り：冒頭の一文【要決定：下の 3 案から】。
- 素材：A1（札）、A2（運営者の PC で Excel、手順書どおり）。

冒頭の一文の案（設計書の「なぜ作るのか」に書かれた事実から）：

| 案 | 一文 | 向き |

### S1　0:12–0:27　業界構造（関係図）

- 画：関係図 1 枚。左に持ち主の市町村、上にプラントメーカーの保全子会社、右に O&M 事業者。施設の箱の中に「整備の履歴」。
  1. 線が出る：市町村 → 施設（持ち主）、保全子会社 → 施設（随意契約で整備）、O&M 事業者 → 施設（入札で運転）。
  2. 「見たい」矢印が 1 本ずつ出て、矢印ごとに一行で理由を添える（計画 §1.1 の 5 行を 3 本にまとめる）。
     - 市町村 → ほかの施設：比べる物差しが無い。
     - 保全子会社 → 他社のプラント：秘密だと諦めている。
     - O&M 事業者 → 入札の対象：外からは見えない。
  3. 最後に、履歴が系列と施設ごとの箱に閉じる絵 → 検問所の画面を 1.5 秒だけ先に見せる。
- 語り：似たプラントと、比べられない。市町村も、保全の会社も、運転を請け負う会社も、見たい履歴は、ほかの誰かが持っている。
- 画面の文言：「全国 844 のごみ焼却施設（環境省 令和 6 年度）」「似たプラントと、比べられない」。一行の説明：「随意契約＝入札をせずに、納めたメーカーの系列に頼む」「O&M＝運転と保全をまとめて請け負う」。
- 会社やメーカーの名前は出さない。
- 素材：A1。HTML を PNG にして、矢印ごとに 1 枚ずつ書き出す。

### S3　0:37–1:05　取り込みから、署名した版まで

- 画：左に Claude Code、右に MOYAI（同じ回から撮る）。
  1. 資料のシートに Excel・PDF・写真を落とす（×4 の早送り）。
  2. Claude が intake_survey で読む →「質問 ○ 件」→ 人が選択肢で答える。
  3. 当てはめ：記録が共通の設備項目 × 作業の属性（点検・分解整備・更新・基幹改良）の行に当たる →「未解決 0」。
  4. 写真は「人が確かめるまで要確認」の札。
  5. 決定のシートで人が「受ける」→「署名して確定する」。トップの「もやいの星取表」に版が 1 つ増える。
  6. 2 秒：素の curl で確定を叩くと拒まれる試験が緑。
- 語り：現場の資料は、Excel も、PDF も、写真もある。Claude は全部を読み、分からないところだけ聞く。どの記録も、国の機器リストの項目に当てる。決めるのは人。署名で、版を結ぶ。
- 画面の文言：「当てはめは AI の案、決めるのは人」「未解決 0」「写真は人が確かめるまで要確認」。
- 素材：B1。デモの台本（`tests/demo/walkthrough.spec.ts`）を、Claude Code を並べた形にして撮る。

### S4　1:05–1:35　パックで広がる

- 画：
  1. 星取表の行が「共通の設備項目 × 作業の属性」であることを寄りで（3 秒以上）。
  2. 検査のシート：パックの基準から外れた所を、根拠の数字と出典つきで出す。札「自己点検」。
  3. 検査の試験が緑（2 秒）。
  4. パックをし尿処理に替えると、同じ画面に別の業種の星取表が出る。`src/` の差分 0 の試験が緑。札「パックを足しただけ」。
  5. 設備の地図の 1 枚（A 市町村の環境〜H 交通）。起点のごみ焼却と、済みのし尿処理に印。ほかの行には「構想」の札。2 段目の「送風機」の行で、焼却の誘引通風機・下水の送風機・ビルの空調機がつながる線。
- 語り：ごみ焼却の国の基準を、データにした。判定はコード、説明は Claude。し尿処理は、パックを足しただけで動いた。ほかの設備も、同じ物差しに並べられる。
- 画面の文言：「検索ではなく判定」「パックを足しただけ（コードの差分 0）」「構想」。
- 素材：B2、A1（地図）。

### S5　1:35–2:20　山場：秘密を出さずに比べる（音楽なし）

- 画：
  1. SHARE の検問所「相手から見たあなた」。844 → 紛れる数。
  2. メモ帳で出す束を開き、施設の名前で検索して見つからない（C2、運営者の PC）。
  3. 合言葉で署名して出す → 公開の台帳に PR → Actions の検証 ✓ → 人がマージ → 台帳のサイト。
  4. 自分の星取表の下に、似た施設の匿名の行（類似施設 A・B…）が重なる。比べる立場を、市町村 → 保全子会社 → O&M 事業者と切り替える。
  5. Claude が台帳から周期の案を置く（朱の破線の円）→ 人が決定のシートで受けて、署名して確定する。
- 語り：比べる単位は、国の機器リストと作業。出すのは、周期と、工数と、日数だけ。費用も、施設の名前も出さない。データベースは置かない。同じ塊を、市町村は全国と、保全の会社は自社の納入先と、運転の会社は入札の相手と比べる。決めるのは人。
- 画面の文言：「塊＝国の機器リスト × 作業」「周期・工数・日数だけ。費用は出さない」「中央の DB なし」。
- 素材：C1（本物の GitHub で撮る【要準備】）、C2。

### S6　2:20–2:40　Claude の使い分け

- 画：
  1. 使い分けの図 4 秒：Skills＝業種のパックと読み方、MCP＝作業画面（今動くツール ○ 個）、フック＝人だけの確定を守る、サブエージェント＝見ていない様式の書き手と答える役。

- 語り：Claude は、役目ごとに使い分けた。読めない様式は、会話で読み方を決めて Skill に残す。承認するのは、版に署名する人。
- 画面の文言：「重みは変えていない」「構想」。
- 素材：A1、B1（読み方のシート）。
