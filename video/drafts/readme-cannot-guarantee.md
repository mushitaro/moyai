# README と画面の「保証できないこと」の材料（Architect、2026-11-05）

plan §2.8 の ①〜⑬ と §2.12 の ①〜⑦ に足す形。README に入れるとき（11-06 夜、PM）に使う。

## 足すもの

- 鍵の短い印（C3 の残り）：鍵を見分ける ID と引き渡しのリンクの印は、指紋の頭 16 文字（64 ビット）。計算の量をかければ、同じ印の別の鍵を作れる。MOYAI は確認済みにするときと承認を数えるときは公開鍵そのもので比べるが、画面とファイル名の短い印だけで人が判断すると取り違えることがある。
- 署名の時刻（F8）：署名の時刻は、署名した人の PC の時計。MOYAI は時刻を証明しない。同じものに署名が 2 つあるときは、確認済みの人の署名を先に見せる。
- 見張りのフック（中-1。§2.8 の ⑪ に足す）：同じ PC の同じ利用者が動かすプログラムは止めきれない。AI が自分で書いたスクリプトを走らせる道や、ブラウザを操る道具からボタンを押す道は越えられる。
- 輪と台帳の両方に出す（中-13。§2.8 の ① と ⑦ に足す）：同じ施設が自社の輪と公開の台帳の両方に出すと、鍵を分けていても、年度と帯の並びから、輪のメンバーは公開の台帳のどの共有ファイルがあなたかを推せる。
- 書き出した Excel（3C）：署名は、書き出した Excel のバイト列を人が見て結んだもの。その Excel が版の中身から正しく作られたかは、署名の中で証明しない。
- 当てはめの呼び名（V-1）：パックの「よくある呼び名」は作る側が決めたもので、原典で照らしていない（未確認）。当てはめは案で、人が受けるまで決まらない。
- 前の版の資料（重-2・1C）：写真から読んだ資料は、次の版へ引き継げない。もう一度渡してもらう。

## 書き分け（正直さ）

- §2.8 の ⑧「置き場所の管理者の隠し事は、鎖で後から気づけるだけ」：D3（79d7972）が入ったので、「版も輪の共有ファイルも、末尾が消されれば後から気づける（前に見たことのある PC だけ）」と書く。
- 承認・差し戻しの署名の消失（監査役の監-2）：鎖は版を作った署名だけを持つので、承認や差し戻しの署名を消されたことに気づけるのは、前にその署名を見た PC だけ。初めて開く PC は気づけない、と 1 行足す。
