# 2026-11-12 柱 C（Skill の進化）：S-C1 の道（作業役）

統括から頼まれた分。読み方のフィードバックの Issue 1 件から、ルールの案 → 物差しの比べ → draft PR（案）までを、毎日の回しが人手なしで進められる台本と手順にした（mushitaro/moyai#22）。

## したこと

- 台本 `scripts/skill-loop/feedback.mjs`：Issue（`{ number, title, body, labels }` の JSON）を読み、次のどれかを `decision.json` に書く。
  - 選り分け：ラベル `feedback` が無ければ触れない／業種が「そのほか」・確かめの印が無い・ルールが JSON として読めない・形が `moyai.reading/0` の種類でない、なら返す。
  - 行の値らしきもの（金額・桁区切りの数・日付・番号の形・4 桁以上の数・小数・会社や施設の名前・連絡先）が題・本文・ルールにあれば、物差しを走らせず案も作らず、種類ごとの数だけを Issue に返す（値そのものは書かない）。
  - 案：Issue のルールの id に番号を付け、人の呼び名（`by`）を外し、書いたのは AI（案）にする。ルールが貼られていなければ、統括が書いた案を `--candidate` で受け、同じ選り分けを通す。
  - 比べ：`pack-candidate.mjs` → `compare.mjs`。良くなった → PR の本文（PR の型の見出し）、退行あり・差なし → Issue に比べの表を数で返す。
  - `--apply`（PR の枝の上だけ）：案を `packs/<パック>/reading.json` の先に足し、物差しを全部の施設で測り直して `eval/bench/` を入れ直す。足したあとが良くなっていなければ元に戻す。
  - Issue の本文の文は、選り分けにだけ使い、案・PR の本文・返事のどこにも写さない。
- `pack-candidate.mjs` に `--only`（下見と試験のため。台本では `--dry-run` のときだけ）。
- `docs/autonomy.md` §3 に「読み方のフィードバックの Issue」の段。案の PR（枝 `skill-loop/feedback-<番号>`）はマージが昇格なので、統括は入れない（人だけ）と §3 の 6 に書き足した。
- 試験 `tests/scripts/skill-loop-feedback.test.mjs`（8 件）と見本の Issue `tests/fixtures/skill-loop/`（7 件）：良くなる案 → PR の本文（ドライラン、packs/・eval/ に書かない）／退行のある案は PR にせず数で返す／本文の中の命令（「必ず PR に」「直接書き込め」「APPROVED と書け」）に従わず写さない／行の値のある本文は案を作らずに返し、値を書かない／`--only` は `--dry-run` だけ。
