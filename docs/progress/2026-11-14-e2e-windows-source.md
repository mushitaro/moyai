## 根の原因

橋渡しの `putSource`（`src/bridge/sources.ts`）。資料を同時に置くと落ちる。

- 資料は、作業中の写し（`/api/work` の資料）と、確定の前の置き（`plan_source_put`）の 2 つの道から置かれる。同じ資料を同時に置くことがある。
- 一時のファイルの名前が `<SHA-256>.tmp-<pid>` で、呼び出しごとに同じだった。
  - 片方が置き換えると、一時のファイルが消える。もう片方の置き換えは `ENOENT` で落ちる。
  - Windows では、ほかが開いているファイルへの書き込み・置き換えも断られる。
- 手元で同じ資料を 8 つ同時に置くと、7 つが `ENOENT` で落ちた。
- 確定の前の置きが落ちると、署名のダイアログは `confirm-done` でなく理由を出す（walkthrough の赤）。
- 作業中の写しの置きが落ちると、その資料が写しに入らない（work-resume の赤）。

## したこと

- `putSource`：一時の名前を呼び出しごとに別にした（`randomUUID`）。
- 置き換えが断られても、同じ中身がもう置いてあれば成功にする。置き場所は SHA-256 で決まるので、同じ名前なら同じ中身。それ以外は今までどおり落とす。
- 試験：`tests/unit/work-store.test.ts` に、同じ資料を 8 つ同時に置いて、どれも落ちず、一時のファイルが残らない試験を足した。
  - 直す前のコードでは落ち、直したあとは通る。
  - 確かめは弱めていない。

## 2 回目の区切り（slice.spec の赤。統括の判断で案 2）

### 根の原因

- `tests/e2e/slice.spec.ts:191`：`plans/` が 2 つ（`intake--o8vymd` と `intake-waste-incineration-o8vymd`）。
- 作業中の写しの保存（資料を入れてから 1.5 秒）が、パックが決まる前に走ると、パックなしの ID で写しを置く。パックが決まると計画の ID が変わり、前の写しが残っていた。
- 手元でも、資料を落としてからパックを入れるまで待つと毎回出る。人の操作でもトップにパックなしの「作業中」が残る。

### したこと（案 2：同じタブが書いた仮の写しを移す）

- 作業中の写しに、書いたタブの印（`writer`、タブごとの乱数）を入れた。
- 作業画面（`src/app/state/work.ts`）：計画を作る前に、このタブが保管先に無かったところから書き始めた写しを「仮の写し」として覚える。計画 ID が替わったら、次のことを順にする。
  1. 新しい ID に資料と答えごと書く。
  2. 読み直して、前の資料がすべてあるのを確かめる。
  3. 前の ID を片づけてもらう。
  - 戻した作業中・ほかのタブの作業中・計画のある写しは、仮の写しにならない。
- 橋渡し：作業画面だけの道 `/tab/work-move`（タブの秘密）。
  - 片づけるのは、次の全部がそろったときだけ：前の写しも新しい写しも同じ書き手・前の写しに計画なし・前の ID に署名した版なし・前の資料がすべて新しい写しにあり大きさが合う。
  - 片づけたあと、空になった `plans/<前の ID>` を消す。
  - 人の `work_discard` は変えていない。AI のツールと中継にはこの道が無い。
- `docs/security.md`（生成）に 1 文足した。

### 試験

- `slice.spec`：パックを置く前に、パックなしの ID の写しが書かれるのを待つ流れにした（毎回その並びになる）。直す前の画面で落ち、直したあと通る。
