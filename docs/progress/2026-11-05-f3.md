# 2026-11-05 F3 Skill の採点（枝 claude/f3-eval-c0aae2）

F3 の関門：ごみ焼却とし尿処理で、Skill の採点の高い評価が繰り返し出るか（再現性）を測る。設計の正本は `docs/plan.md` §2.10。

## したこと

- `node dist/cli.js eval` を作った（`src/eval/`。入口の `src/cli/main.ts` に足したのは eval の 1 行だけ）。
  - `eval gen --pack <パック> --world <正解の世界>`：問題を作り、`eval/<suite>/`（`suite.json`、`cases/{train,test}.jsonl`）に置く。
  - `eval run --suite <名前> --max-usd <上限>`：送る文の全文を `eval/runs/<runId>/outbound.txt` に書き、固有名詞の当たり・試験用の問題の混入・費用の見込みを出してから、Messages API で 1 問 3 回走らせる。`manifest.json`・`results.jsonl`・`report.json`・`report.html` を置く。`--dry-run` は API を呼ばない。費用を測るための `--per-rule <n>`（規則ごとに先頭の n 問）もある。
  - `eval report --run <回> [--base <前の版の回>]`：`results.jsonl` から `report.json` と静的な表（`report.html`）を作り直す。`--base` で自動の見立てを付ける。
- 問題の生成器：工場の正解の世界（`samples/truth/`）とパックのデータだけから、規則 10 × 10 問を決まった種（20261105）で作る。業種の語はコードに置かない（パックの 1 段目・機器・検査の名前とパックの id が `src/eval/` に無いことを試験で見る）。
  - R01 周期の欄が空なら推測しない／R02 番号の違う機器を名前でまとめない／R03 出典はパックの一覧の中から（このパックに無い検査は「パックに無い」が正解）／R04 年度の始まりはパックどおり／R05 記録に無いことは「記録に無い」と言う／R06 和暦の年度／R07 範囲のタグ（「1～2号炉」）を機器ごとに分ける／R08 凡例に無い記号の意味を推測しない／R09 合計・小計の行を作業にしない／R10 単位の違う工数（時間の工数は、1 人・日の時間が記録にあるときだけ数にする）。
  - 分け方：作業の年度が 2023 年度より前を学習用、以後を試験用（期間）。年度を持たない R03・R08 は問いの番号 1〜5 と 6〜10。
  - 本文を正規化（NFKC・空白と記号を落とす）してハッシュを取り、同じものを除く（今回は 0 件）。試験用の問題のハッシュを `suite.json` に書き、Skill の文に試験用の問題の記録の行が入っていれば走らせない。
  - 施設名・業者名は「施設A」に置き換え、送る文の固有名詞の当たりを、束とは別の関数（`countEvalProperNouns`）で数える：両パックとも 0。
- コードの採点 6 種（`src/eval/grade.ts`）：JSON として読めるか／推測で埋めていないか（周期・工数・印。記録にある値は合っているか）／番号の違う機器を名前でまとめていないか（対象の集合が正解と同じか）／出典がパックの一覧の中にあるか／年度がパックどおりか／記録に無いことを「記録に無い」と言えたか。答えの形が崩れたら、その問いの確かめは全部落ちにする。
- 走らせる条件（`src/eval/run.ts`）：モデルと effort は `config/models.json` の `eval` の項目から取り、effort を毎回明示する。温度・top_p・top_k・thinking・fallbacks は渡さない。system（前置き＋Skill）はキャッシュする。max_tokens は 16,000。送り直しは SDK の既定を切り、込み合い（408・409・429・5xx・529・つながらない）だけを 10・30・60・120 秒待って送り直す。記録にはモデルの識別子を書かず、項目名「eval」とそのハッシュ、応答のモデルが頼んだものと同じだったかだけを書く。切り替え・拒否・max_tokens・誤りの回は集計から外し、理由ごとに数える。誤りは状態の番号だけを残す。
- 費用：1 回ごとに `results.jsonl` に、回の合計を `manifest.json`・表・`ops/api-spend.jsonl`（役 eval → 配分 f3）に書く。走らせる前に見込みを出し、`--max-usd` を越える見込みなら止める。走っている途中も、使った額と走っている呼び出しの見込みが上限を越えそうなら、新しい呼び出しを始めない。台帳の配分（`config/models.json` の budgetUsd）も呼ぶ前に確かめる。
- 自動の見立て（`src/eval/report.ts`。決めるのは人）：過半の回で落ちる問題が増えた → 退行あり。合格率の差が前の版の揺れの幅に収まる → 差なし。ほか → 承認待ち。揺れの幅は、前の版を 3 回走らせたときの回ごとの合格率の最大と最小の差で、定数は `BAND_RUNS` の 1 か所。小さな差を「改善」と書かない。
- 保存と昇格のコマンドは作っていない（人だけがする）。
- 正解の世界の入口を形ごとに分けた（主線の指示）：`src/eval/worlds/factory-v1.ts`（今の工場の `world.json` と `*.truth.json`）と `src/eval/worlds/answer.ts`（運営者の指示書 §5 の `answer/world.json` と `answer/files/`）。`eval gen --world` はフォルダの中を見て形を見分ける。生成器は、どちらの形からでも同じ `WorldData` を受ける。
  - 指示書 §5.2 は中身（機器・実際に行った作業・資料の結び・欠け・profile）を決めているが、項目の名前までは決めていない。だから項目の名前の候補を `ANSWER_FIELDS` の 1 か所に置き、どの候補も無い要る項目は推測で埋めず、無い項目の名前を挙げて止まる。新しいサンプルができたら、そこだけを合わせる。
  - 年度は、世界の日付からパックの年度の始まりで出す。1 人・日の時間・凡例に無い記号が世界に無ければ null にし、R10・R08 の問いを作らず「作れなかった問い」に理由つきで数える（8 時間などと置かない）。
  - answer の形は、新しいサンプルがまだ無いので、試験が一時のフォルダに置く小さな架空の世界（機器 7・作業およそ 120）でだけ試した。その世界には予定と凡例に無い記号が無いので、R08 の 10 問が「作れなかった問い」になり、ほかの 90 問は作れた。本物の answer の形では未確認。
