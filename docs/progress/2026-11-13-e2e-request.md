# 2026-11-13 日誌：main の e2e の赤（request.spec の「取り下げられたリンク」）（作業役）

統括から頼まれた分。main の 6b342de の CI で e2e (ubuntu-latest) が落ちた。落ちたのは `tests/e2e/request.spec.ts` の「佐藤：古いリンクで『受け取る』を押すと…取り下げられました」で、`request-receive` が出なかった。同じ木の PR の回では通っていた。枝は `claude/bench-v3-frozen`（PR #115 に足した）。

## 根の原因

画面の不具合。試験だけの問題ではなかった。

- 試験は `pc.goto(#/)` → `pc.goto(古いリンク)` と、hash だけの移動を 2 つ続ける。
- 描き直しが 2 つの移動のあとに 1 回にまとまると、版の画面（Merge）は外へ出ないまま残る。
- 版の画面は、開いたリンクを `open`・`v`・`h` の組で「開き終えた」と覚えている。同じリンクでは開き直さない。
- そのため、前の段の「ほかの鍵が受け取っています」（見るだけ）が残り、「受け取る」が出なかった。
- 人の操作でも、トップへ出てすぐ同じリンクを開くと同じことが起こりうる。

## したこと

- `src/app/App.tsx`：hash の移動ごとに、行き先（`newURL`）が版の画面の外なら数を 1 つ上げ、版の画面の `key` にした。
  - 外へ出て戻ったら、描き直しがまとまっても、版の画面は前の状態を持ち越さず開き直す。
  - 行き先は `location.hash` ではなく `newURL` で見る。`location.hash` は、続いた移動の最後の行き先になっているため（最初の直しはこれで効かなかった）。
- `tests/e2e/request.spec.ts`：その段を、2 つの hash の移動を描き直しの前に続けて起こす形にした。
  - 間欠で起きていた並びを、毎回起こす。
  - 直す前の画面では毎回落ち（2 回）、直したあとは通る。
  - 確かめは弱めていない。
