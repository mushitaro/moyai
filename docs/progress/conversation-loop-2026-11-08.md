## 穴（重い順）

1. **「参考として計画に使わないか」の決まった答えが、問われていない資料にも効いた。**
   - match「は、今回は参考として計画に使わないか」・答え reference のルールを置いた。
   - 問われていたのは 5 本なのに、47 本すべてが外れた。
   - 質問 0・未解決 0 と返り、作ると「計画に使う資料が無い（どの資料も参考として外した 47）」になった。
   - 決まった答えは、画面に出ていない（隠れた）資料ごとの問いにも当たっている見込み。
2. **行の役割は「行のどれかのセル」に当たる。頭の字で絞ると、ほかの資料の行が丸ごと消える。**
   - 「【架空】」で始まる行を注記にしたら、93,987 セルに当たった。
   - 発注明細の仕入先名「【架空】東浜耐火」なども同じ字で始まるので、明細の行が丸ごと注記になった。結び付きは 1,631 → 0。
   - 答えは成功の形で返り、気づけるのは効いたセルの数が跳ねたことと、別のルールの数が 0 になったことだけ。
   - ツールの説明に「どれかのセル」と書いていない（コードの注にだけある）。
3. **決まった答えは、2 回目の資料の切れ端を黙って通す。**
   - 「先の資料に無い機器は入れる」が、頁の頭書き「【架空】青葉台環境センター」を機器として 266 節入れた。
   - 質問 0 のまま計画ができ、利用者には見えない。
   - 計画を作ったときに、資料ごとの新しい節の数か、同じ名前が多くの頁に出る節を知らせる道が要る。
4. **PDF の報告書の実績が計画にほぼ入らない。**
   - 3 列の表の折り返しで機器名・作業・結果が切れ端になる（「ごみク」「レーン」）。
   - 質問の答えは「外す」「備考」だけ。
   - 6 年分の報告書を足しても、作業は 89 しか増えない。
5. **2014 年度の診断記録（診断カード）を読む形も、資料を外す形も無い。**
   - 行の役割 26 で減らしても、所見の文の切れ端が第 1 階層に残る（星取表の頭の 60 行はどれも切れ端）。
6. **下書きのルールを消す道が無い。**
   - 一覧から抜いて置き直しても残る（同じ id は置き換え、抜いた id は残る）。
   - 当たらない字に置き換えて止めたが、そのルールは下書きに残る。登録すると保管先に入る。
7. **reading_rules_propose の答えが当てにならないときがある。**
   - 12 回のうち 4 回が時間切れ（「時間内に答えが来なかったので、結果は不明です…」）。どれも結果は入っていた。
   - 2 回目の呼び出し（ルール 14）は、どのルールも効いた数 0 と返った。実際には効いていて、質問 0・未解決 0 になっていた。
8. **作業の名前に「予:」が付いたまま、見出しの切れ端「作業・期間」が作業になる。**
   - 「予:」は中長期計画の xlsx から来ている。
9. **ツールの説明とスキーマのずれ。**
   - スキーマに effortTrade（職種の語）があるのに、reading_rules_propose の説明に無い。
   - rowRole の当たり方（どれかのセル、NFKC・空白を除く）が説明に無い。
10. **intake_survey の答えが重い。**
    - limit: 1 でも、入れた資料の一覧（2 回目は 86 本）を毎回返す。
    - 質問の頁も 1 回 60 KB の上限まで来る。
    - 詰まった行を見るだけでも 1 回が大きく、会話の量を食う。
11. **show: true で開き直すと、作業画面は空になる。**
