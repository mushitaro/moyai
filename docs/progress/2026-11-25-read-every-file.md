# 2026-11-25 標準に合わない資料を、外さずに読み切る（帳票の型・契約の欄）

運営者の指摘（2026-11-25）：デモ v4（【架空】さくら坂焼却場の発注台帳 CSV・日報）と Maximo 連携のデモで、AI が「標準の Skill に合わないから資料を外す」方へ流れた。帳票の構造を読み、カスタムスキル（読み方のルール）を作って読み切る方へ変える。

## 前の決まりとの関係

- PR #142 の「読み手を直さず、選ぶ資料を変える」は、デモ v4 の作業の範囲の決まりだった。読み手（取り込みの層）は今回も変えていない。
- 足したのは 3 段の規則の種類だけ（plan.md §2.17「言えないときだけ規則の種類を足す」のとおり）。ルールの無い資料の読み方は変わらない（物差しの値は main と同じ）。

## したこと

- 読み方のルールに 2 種類を足した（`src/import/reading.ts`）。
  - `form`（帳票の型）：題・頭書きの項目（日付・機器・単位・工数など）・作業の行の見出しを言うと、1 枚 1 日の日報を「頭書き＋作業の行」として読む。
  - `contractColumn`（契約の欄）：契約の表で、どの列が何か（債権者名＝vendor など）を言う。
  - `headerRow` のルールの行は、繰り返しの見出しとして外さない（2 つ目の表の見出し）。
- AI が資料・行・欄を「外す・参考・断る」と決めるのを止めた：`intake_settle` は author が ai の外す答えを `drop_needs_user` で返す。外すのは人の言葉（ai_relayed_human）だけ。
- 1 段目の Skill に「Read every file」の手順（構造を見る → ルールの種類を選ぶ → 案を出して読み直す → 登録 → ルールで言えないことだけ聞く → 種類が無ければフィードバック）。instructions の決まりの 4 番にも 1 文（4,096 字に収めた）。
- ごみ焼却のパックの SKILL.md とデモの README に、日報と発注台帳を読み切るルールの例と測った値。
