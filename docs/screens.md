# MOYAI の画面の仕様

Wire のセッション（画面の設計）が 2026-11-04 に書き、Dev に渡したもの。`docs/plan.md` §2.14（画面と主ボタン）を置き換える。
作る順（5 章の P0 → P1 → P2）は、運営者が 2026-11-04 に Wire のチャットで決めた（「この順で」）。
正本の絵は Wire のキャンバス（Artifact。運営者だけが開ける）。下の「絵」の欄がそのファイル名。

## 0. 考え方（運営者が決めたこと）

- 引き算。1 つの画面に、目的を 1 つ、人の操作を 1 つだけ置く。
- 決めるのは Claude との会話でする。質問への答え、周期の直し、様式の写し方、出す範囲、読み方がそれに当たる。
- MOYAI は、見て確かめる面。人だけの操作（確定＝署名、渡す、承認、書き出し、出す）をここで押す。
- 画面には、画面の説明の文と「Claude に話す『…』」の例を置かない（運営者、2026-11-04：「アプリの説明は、AI にしてもらってもいい」）。初めて使う人への説明は Claude がする。各画面の短い説明（何を見る画面か・人が押すのは何か）は MCP の instructions と基本の Skill にある（src/shared/instructions.ts）。
- 残す文は、説明ではなく状態や結果を言うものだけ：押せない理由、戻せない操作の前の結果の文（渡すと編集の番が移る、公開の台帳に出したら相手の写しは消せない）、中身が空のときの 1 行。検査の「自己点検であって、審査の判断ではない」も画面には出さない（運営者、2026-11-04：意味が分からない。分かる文で戻すかは未定）。Claude の側の決まり 5 と、check_results の結果には残す。
- 重要度の順に置く（運営者、2026-11-04）：データ → 決まっていない所と署名（横の板）→ どの施設のどの版か → シートの切り替え → 比べる版・似た施設 → Claude への話し方の例。見出しの下やタブの下の説明の文は置かない。
- 色は墨と朱だけ。成功や注意は形（✓ ! ×、左の罫）と言葉で分ける。teal・red・green は使わない。

## 1. 骨組み（Shell）

- ヘッダ（運営者、2026-11-04：「MOYAI と MERGE の間も、ほかのタブ名と同じく › で並べる。間も等間隔に」）
  - 左から、しるし（25×20、飾り）→ 段の列「MOYAI › MERGE › EXPORT › SHARE」。MOYAI は段の列の最初の項目（トップへ）。144px の塊はやめた。
  - 段の列の中は、項目と「›」の間をすべて 20px。「›」は本文の字（12px、--text-disabled）。
  - しるしと MOYAI の間：トップ（MOYAI が今の段で大きい）では 10px（しるしと字の組み）、ほかの段では 40px。
  - 今の段は 17px/24px・字間 0.18em・--text。ほかの段は 10px・--text-3。下線は引かない（「大きく、ほかはグレーアウト」）。
  - 右：暗 / 明、設定。
  - LEDGER / IMPORT / CHECK のタブは無くす。
- 状態の帯：左から「- 架空」、つながり。右端にビルドの印。
- 開発の道具（確定の試し・前の画面への道・Ed25519 の試験のページ）は、設定の画面の下に置く（会期のあいだだけ）。トップには置かない。

## 3. 画面ごと

### 3.1 MOYAI（トップ）　絵：Main.dc.html

- すること：どの施設の、どの版から始めるかを選ぶ。主ボタンは無い。トップは星取表だけ（説明の文は置かない）。中身は左 32px から（中央に寄せない）。
- もやいの星取表：行は施設（派生は字下げ）、列は今月までの 20 か月（44px）、印は版（● は署名した版、朱の ○ は編集中か承認待ち、朱の × は確かめで合わない版）。凡例は星取表の下。
- 行の名前のすぐ右に、版（「第 7 版」、等幅）と状態（「編集中」/「承認待ち」、朱）。
- 派生：親の版の印から細い線（--text-3、1px）を下ろし、子の行の最初の印へつなぐ。
- ほかの人が持っていた間：印の下に 2px の線と「後任が持ち、戻した」のような添え書き。
- 入口は 3 つ：行の右端「＋ 次の版」、版の印のメニュー（開く / この版から次の版 / この版から別の施設をつくる）、星取表の下「＋ 新しい施設」。どれも MERGE へ。
  - 開く：いちばん新しい版なら、そのまま MERGE で重ねられる。古い版は見るだけ（見出しに「保管先の古い版（見るだけ）」、下の帯の止め札「保管先の古い版を見ています…」）。
  - この版から次の版：その版の中身を作業中の計画に置き、保管先のいちばん新しい版の次の版をつくる。比べる版はいちばん新しい版（MERGE の上に「第 n 版の中身から、次の版をつくります。」）。
  - この版から別の施設をつくる：新しい施設の名前を決め（架空の施設からなら【架空】を付ける）、その版の中身を写して MERGE へ。第 1 版に署名すると、元の計画・版・中身のハッシュを版の記録（derivedFrom）に書く。橋渡しは、元の版が確かめで合い、ハッシュが同じときだけ書く。
  - ほかの人が作った版：印の下に 2px の線と、印の名前（title）に作った人の呼び名。凡例「━ ほかの人が作った版」。
- トップでは資料を受けない。施設が無いときは「＋ 新しい施設」だけ。

### 3.2 MERGE（版に重ねる）　絵：Review.dc.html

- 上は 2 行だけ（運営者、2026-11-04：「見出しの下の文や、タブ名の下の説明が幅をとって、肝心のデータの場所が小さい。工場名も大きすぎる」）。その下はすぐデータ。
  1. 見出しの 1 行（main の上の余白 24px）：施設の名前（17px・500・字間 0.1em）、「第 7 版」（等幅 13px・--text-2）、状態（編集中 / 承認待ち / 差し戻し、朱 12px）。右寄せで「比べる版　第 6 版」「似た施設　重ねる / 外す」（既定は外す）「施設の設定」（12px）。
  2. シートのタブの 1 行。
- 見出しの下の説明の文、タブの右の「画面のどこに落としても…」は置かない。ファイルを引きずって画面に入ったときだけ、全面に「第 n 版に重ねます」と出す。
- シートのタブ（この順）：星取表｜突き合せ（資料が 2 つ以上のとき）｜読み方 n｜検査｜決定 n｜「重ねた資料」の札と、資料ごとのタブ｜＋ 資料を足す。
- 星取表のシートの上は、表示の切り替え（自分の台帳の段 / 共通の設備項目 × 作業の属性・年度だけ / 月まで・元の計画 / 調整後）の 1 行だけ。凡例は表の下の 1 行で、行の数はその右端に小さく。「見えている行…」「畳んだ行をダブルクリックすると…」などの説明の行は置かない。
- 比べる版：編集する人は保管先のいちばん新しい版、承認を頼まれた人は頼まれた版のひとつ前の版。保管先に版が無ければ出さない。
- 見出しの状態と下の帯の左は、いま開いている版（つくっている版）のこと（Wire、2026-11-04）：編集の番が人に渡っている（編集を頼んだ・承認待ち・差し戻し）ならその番、番が空いていれば次の版を「編集中」・「編集の番 あなた」。「確定済み」は古い版を見るだけで開いたときだけ。
- 朱は 1 つの意味・1 つの形（朱の印と、印の下の短い朱の線）：比べる版があれば「第 n 版から変わった」（この版の中で人が調整した所も含む）、無ければ「元の資料から変えた所」。
- シート「星取表」：前の版から変わった印は朱（印のすぐ下に短い朱の線。凡例「第 n 版から変わった」）、前の版にあって今は無い印は淡い破線の小さな円（凡例「第 n 版の印」）、決まっていない所は朱の「?」。コメントの付いた行は ①②。似た施設を重ねると、各行の下に細い行「似た施設　帯 3〜5 年」（5 施設に満たなければ「似た施設　5 施設に満たない」）。自分の計画に無い項目の行は、名前だけを淡く出す（似た施設の行はその下）。
  - 重ねているあいだ、星取表の上に出すのは「市町村 | 保全子会社 | O&M 事業者」の切り替えと、「公開の台帳　似た施設 7　| 見え方を直す」の 1 行だけ（台帳の ID は出さない。輪があれば「輪　似た施設 n」も同じ行に）。O&M のときだけ、入札の対象の見え方の欄を足す（対象は自分の施設ではないので、施設の設定には置かない）。
  - 見え方の答え（全国の表に載るか・炉の型・処理能力の帯…）は施設の性質なので、施設の設定の 1 か所だけで答える（Wire、2026-11-04）。答えていなければ、その 1 行に「似た施設　見え方が決まっていません　| 施設の設定で決める」。比べるのに使う軸は、パックの主要の軸（人は選ばない）。
- 施設の設定（版があるあいだは小さなダイアログ）：見え方（全国の表に載る施設か・見え方の軸）。答えは作業中の計画の施設の欄に置き、次の版に署名すると版に残る。SHARE の見え方の答えは、ここから先に入る。規模から読める帯は見込みとして先に選んでおき、人が決める。
- シート「突き合せ」（絵：Match.dc.html）：資料ごとの書き方を並べ、「✓ 一致」「! 片方だけ」「× 食い違い」。切り替えは「食い違い / 片方だけ / すべて」。
- シート「読み方」（絵：Reading.dc.html）：データは `src/app/state/reading-tab.ts` の readingTab()。
- シート「検査」：外れた所を「自施設 → 基準」の数字と出典を添えて 1 行ずつ。外れは朱の「×」、満たすは「✓」、当たらないは「―」。
- 台帳の案の印（星取表のシート）：台帳から Claude が置いた案は、まだ決まっていないので「前の版から変わった」（朱の線の円＋下の 2px の朱の罫）と分ける。
  - 案は朱の破線の円（10px、1px dashed --shu）。下の罫は付けない。字の ○ は DOM に残す。
  - 凡例に「○（朱の破線）Claude の案（決定のシートで受けるまで決まらない）」を足す。
  - 人が受けたら、ふつうの「前の版から変わった」朱の印になる。絵：Review.dc.html（送風機 › 分解整備 の 2029 年度）。
- シート「決定」（§2.9 の人が受けていない決定）　絵：Decisions.dc.html
  - タブは「決定 n」。n は受けていない数で、朱。
  - 上に「受ける理由」の欄を 1 つと、副のボタン「まとめて受ける」。1 行ずつ受けるときも、この欄の理由を使う（行ごとの理由の欄は置かない）。理由が空のあいだは押せず、横に「理由を書くと押せます」。
  - 受けていないものを先に並べ、受けたもの・断ったものは下にたたむ。行は箱にせず、罫線だけ。
  - 当てはめの案は、受けるのほかに「断る」（確かめのダイアログを通す）。
  - 表の列：何を｜なぜ｜決めた人｜行（数）｜受ける。
    - 「何を」の下に、種類を朱の小さな字で：「- 台帳からの案」「- 当てはめの案」「- 会話から写した答え」「- Claude の決定」。
    - 当てはめの案（Claude が置いた「節 → 共通の設備項目」の規則）は 1 規則 1 行。何を「「焼却炉本体」の下の節 → 燃焼設備 › 焼却炉」、行（数）は当てた節の数（Wire、2026-11-04）。
    - 決めた人の言い方：「Claude（台帳から）」「Claude（あなたの答えを写した）」「Claude」「あなた（画面で）」。
    - 受けた行は、ボタンの代わりに「✓ 受けた」（淡い字）。
  - 台帳からの案の「なぜ」には根拠の数字を書く（例「似た施設 6 の帯 6〜8 年。前の実績 2024 年度から 5 年」）。費用は書かない。
  - 下の帯「受けていない決定が n つあります。受けると確定できます。」主ボタン「署名して確定する…」は 0 になるまで押せない。
- 資料のシート：元の表をそのまま見せ、読み取った所と未解決のセルを示す。写真のシートでは上に「! Claude に渡してよいか、あなたの許しを待っています」と「渡す」（人だけ）。読んだ格子は画像と並べて確かめる。
- 横の板は 1 枚（地は --layer-1、上の余白 24px で見出しの行とそろえる）。切り替えは「決まっていない所 n / 署名 n / 出どころ / コメント n」（Wire、2026-11-04）：決まっていない所（取り込みの質問）を先頭に置く。n が 0 なら、その切り替えを出さない。出どころは星取表のシートのときだけで、印を選ぶと出どころへ切り替わる（星取表の中に別の板を置かない）。
  - 決まっていない所：同じ書き方の行をまとめた質問 1 つ、既定の答えに「- 既定」、行の数、ラジオ、「決める」。下に「Claude につないでいるときは、会話で答えても同じです。」下の帯の止め札「決まっていない所が n」を押すと、この切り替えになり、資料のシートの該当のセルへ跳ぶ。
- 横の板の署名とコメント：署名は版の中身のハッシュ（4 文字 × 2 組を 4 つ）、使った読み方（下書きは朱の「- 下書き」）、結び目の鎖（確定・編集・承認。✓ は確かめた、朱は待っている）。コメントは ①② の行・文・呼び名・時刻と、書く欄。
- 下の帯（立場で変わる）は、理由とボタンだけ：編集の番の人は、左に止める理由、右に主ボタン「署名して渡す」。承認を頼まれた人は、左に「承認を頼まれています」だけ（編集しないので「編集の番」は出さない）、右に「理由を添えて差し戻す」（副）と「承認して署名する」（主）。承認を頼んだ人は「承認待ち　承認する人 …」。編集の番でない人は見ることとコメントだけ。

### 3.3 MERGE の白紙（新しい施設）　絵：MergeNew.dc.html

- 施設の欄（パック・施設の名前・年度の始まり・架空か）は白紙の欄に置き、版ができたあとは、見出しの施設の名前の横の文字のリンク「施設の設定」から開く。
- 計画を作るボタン：白紙のあいだは、下の帯の右端の主ボタン「第 1 版をつくる」の 1 つだけ（上には置かない。押せない理由はその左）。版があるときは、資料のシートの副のボタン「資料を重ねて第 n 版をつくる」。決まっていない所が 0 になるまで押せない（Wire、2026-11-04）。
- パックの欄は日本語の名前だけ（内部の ID を出さない）。資料の【架空】の印は、欄の印（架空の資料）で分かるので、説明の文は置かない。

- 見出しは「新しい施設」。欄は施設の名前、パック、元の版（白紙なら「なし（白紙から）」、派生なら「B 町 第 3 版」）。
- シートのタブは「＋ 資料を足す」だけ。下に大きな落とし場所。
- 下の帯「資料を落とすと、Claude がまとめて第 1 版をつくります。」主ボタンは押せない（理由を横に出す）。

### 3.4 署名して渡す（ダイアログ）　絵：Handoff.dc.html

- 題は「第 7 版に署名して渡す」。この順に並べる：件数の 1 行（「第 6 版から：足した印 n・消した印 n・変えた印 n」）→ 頼むこと（渡さずに自分で確定する / 編集を頼む / 承認を頼む）→ 宛先（メール）→ ひとこと → この署名で承認する読み方 → 合言葉 → リンクが運ぶもの → ボタン。
- 差分の行の表はダイアログに入れない（差分レポートと決定のシートが持つ）。
- ひとことは 1 つの欄で、版の理由（空は通さない）と、宛先へのメールのひとことを兼ねる。
- 外へ出ていくものは 1 文だけ：見出しの位置に「メールが運ぶのは、版の場所とハッシュだけです」（Handoff.dc.html、Version 39）。
- 鍵の説明の文は置かない（欄の名前「署名の鍵の合言葉を決める（8 文字以上）」で足りる）。鍵を作ったあとの指紋の文も出さない（指紋は横の板の署名に出る）。
- 署名したあとの結果は 1 文だけ：「第 1 版に署名しました。」、渡したときは「第 1 版に署名して、［宛先］へのメールを用意しました。」とメールの文。保管先のファイルの道は出さない（版と差分レポートは EXPORT から落とす）。メールを送るのは利用者のメーラーか Claude で、MOYAI は送らない。
- ボタン：「戻る」「自分のメーラーで開く」（副）、「署名して送る」（主）。署名は人が合言葉でし、そのあと Claude が連携したメールから送る（決まり 1 の例外の 1 つめ）。

### 3.5 EXPORT　絵：Export.dc.html

- 確定した版から Excel を落とす。差分レポートも副のボタンで落とす。
- 書き出しは、EXPORT の画面で人が押したときだけ。Claude のツールは作らない（運営者の決定、2026-11-04、Wire のチャットで）。
- 様式に写す（P2 の 7）：「別の様式を落とす」で利用者の様式（.xlsx）を読む（このタブのメモリだけ。保管先にも AI にも渡さない）。
  - 見出しの行（上から、2 つ以上の欄に字がある最初の行）の言葉から、列の上に写すものを出す：「← 項目」「← 作業」「← 周期」「← 2026 年度の印」（R8・令和8年度・2026年度・FY2026）。決まらない列は朱の「- 写すものが未定」で、何も写さない。違えば人が列ごとに直す。
  - 確定した版の作業を、機器の名前 × 作業ごとに 1 行（同じ機器の同じ作業は印を合わせる）。周期は印の年度の差でいちばん多いもの。年度の印は ○ 計画・● 実施・◎ 両方。
  - 「この様式で落とす」で、見出しの行の下から写した Excel を落とす（人が押したときだけ）。

### 3.6 SHARE　絵：Share.dc.html

- 今の検問所の中身は変えない（相手から見たあなた、出ていくもの、合言葉と送る）。
