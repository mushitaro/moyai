# MOYAI の画面の仕様

Wire のセッション（画面の設計）が 2026-11-04 に書き、Dev に渡したもの。`docs/plan.md` §2.14（画面と主ボタン）を置き換える。
作る順（5 章の P0 → P1 → P2）は、運営者が 2026-11-04 に Wire のチャットで決めた（「この順で」）。
正本の絵は Wire のキャンバス（Artifact。運営者だけが開ける）。下の「絵」の欄がそのファイル名。

## 0. 考え方（運営者が決めたこと）

- 引き算。1 つの画面に、目的を 1 つ、人の操作を 1 つだけ置く。
- 決めるのは Claude との会話でする。質問への答え、周期の直し、様式の写し方、出す範囲、読み方がそれに当たる。
- MOYAI は、見て確かめる面。人だけの操作（確定＝署名、渡す、承認、書き出し、出す）をここで押す。
- どの画面にも「Claude に話す　「…」」の例を 1 行置く。会話で何を頼めばよいかを示すため。
- 色は墨と朱だけ。成功や注意は形（✓ ! ×、左の罫）と言葉で分ける。teal・red・green は使わない。

## 1. 骨組み（Shell）

- ヘッダ
  - 左：しるし＋「MOYAI」（144px の塊）。字はトップでは 17px・--text、ほかの段では 10px・--text-3。
  - 中：段のタブ MERGE › EXPORT › SHARE。今いる段は 17px/24px・字間 0.18em・--text。ほかの段は 10px・--text-3。
  - 右：暗 / 明、設定。
  - LEDGER / IMPORT / CHECK のタブは無くす。
- 状態の帯：左から「- 架空」、つながり、編集の番（MERGE のとき「編集の番　あなた」）。右端に保管先のパス、ビルドの印。

## 2. 前の画面 → 新しい画面

| 前 | 新しい |
|---|---|
| 作業画面（Home） | MOYAI（トップ）：もやいの星取表 |
| 取り込み（Intake） | MERGE の中へ。資料はシートのタブ「＋ 資料を足す」かドロップ。質問は会話でする |
| 星取表（StarTable） | MERGE のシート「星取表」 |
| 検査（Review） | MERGE のシート「検査」 |
| 検問所（Checkpoint） | SHARE（中身はそのまま。運営者の画面の約束） |
| 受け取り箱 | SHARE の中の「受け取った束」 |
| 設定 | 設定（ヘッダの右）。業種・AI に渡るもの・採点も、ここからのリンクにする |
| （無し） | EXPORT：確定した版の Excel を落とす |

## 3. 画面ごと

### 3.1 MOYAI（トップ）　絵：Main.dc.html

- すること：どの施設の、どの版から始めるかを選ぶ。主ボタンは無い。
- もやいの星取表：行は施設（派生は字下げ）、列は月、印は版（● は署名した版、朱の ○ は編集中か承認待ち）。
- 行の名前のすぐ右に、版（「第 7 版」、等幅）と状態（「編集中」/「承認待ち」、朱）。
- 派生：親の版の印から細い線（--text-3、1px）を下ろし、子の行の最初の印へつなぐ。
- ほかの人が持っていた間：印の下に 2px の線と「後任が持ち、戻した」のような添え書き。
- 入口は 3 つ：行の右端「＋ 次の版」、版の印のメニュー（開く / この版から次の版 / この版から別の施設をつくる）、星取表の下「＋ 新しい施設」。どれも MERGE へ。
- トップでは資料を受けない。施設が無いときは「＋ 新しい施設」だけ。
- Claude に話す：「B 町の第 3 版から、E 村の計画をつくって」

### 3.2 MERGE（版に重ねる）　絵：Review.dc.html

- 見出しは施設の名前＋版（「第 7 版」）。説明「…の編集を受け取り、重ねました。第 6 版から変わった所を朱で示します。」
- 「比べる版　第 6 版」。似た施設は「重ねる / 外す」（既定は外す）。
- シートのタブ（この順）：星取表｜突き合せ｜読み方 n｜検査｜決定 n｜〈重ねた資料ごと〉｜＋ 資料を足す。右に「画面のどこに落としても、第 7 版に重ねます」。
- シート「星取表」：前の版から変わった印は朱、前の版の計画は破線の円、決まっていない所は朱の「?」。コメントの付いた行は ①②。似た施設を重ねると、各行の下に細い行「似た施設　帯 3〜5 年」（5 施設に満たなければ「似た施設　5 施設に満たない」）。
- シート「突き合せ」（絵：Match.dc.html）：資料ごとの書き方を並べ、「✓ 一致」「! 片方だけ」「× 食い違い」。切り替えは「食い違い / 片方だけ / すべて」。
- シート「読み方」（絵：Reading.dc.html）：データは `src/app/state/reading-tab.ts` の readingTab()。
- シート「検査」：外れた所を「自施設 → 基準」の数字と出典を添えて 1 行ずつ。冒頭にいつも「自己点検であって、審査の判断ではありません。」。外れは朱の「×」、満たすは「✓」、当たらないは「―」。
- 台帳の案の印（星取表のシート）：台帳から Claude が置いた案は、まだ決まっていないので「前の版から変わった」（朱の線の円＋下の 2px の朱の罫）と分ける。
  - 案は朱の破線の円（10px、1px dashed --shu）。下の罫は付けない。字の ○ は DOM に残す。
  - 凡例に「○（朱の破線）Claude の案（決定のシートで受けるまで決まらない）」を足す。
  - 人が受けたら、ふつうの「前の版から変わった」朱の印になる。絵：Review.dc.html（送風機 › 分解整備 の 2029 年度）。
- シート「決定」（§2.9 の人が受けていない決定）　絵：Decisions.dc.html
  - タブは「決定 n」。n は受けていない数で、朱。
  - 説明「Claude が決めたことと、会話から写したあなたの答えです。受けるまで、版は確定できません。」
  - 上に「まとめて受ける理由」の欄と、副のボタン「まとめて受ける」。理由が空のあいだは押せず、横に「理由を書くと押せます」。
  - 表の列：何を｜なぜ｜決めた人｜行（数）｜受ける。
    - 「何を」の下に、種類を朱の小さな字で：「- 台帳からの案」「- 当てはめの案」「- 会話から写した答え」「- Claude の決定」。
    - 当てはめの案（Claude が置いた「節 → 共通の設備項目」の規則）は 1 規則 1 行。何を「「焼却炉本体」の下の節 → 燃焼設備 › 焼却炉」、行（数）は当てた節の数（Wire、2026-11-04）。
    - 決めた人の言い方：「Claude（台帳から）」「Claude（あなたの答えを写した）」「Claude」「あなた（画面で）」。
    - 受けた行は、ボタンの代わりに「✓ 受けた」（淡い字）。
  - 台帳からの案の「なぜ」には根拠の数字を書く（例「似た施設 6 の帯 6〜8 年。前の実績 2024 年度から 5 年」）。費用は書かない。
  - 下の帯「受けていない決定が n つあります。受けると確定できます。」主ボタン「署名して確定する…」は 0 になるまで押せない。
- 資料のシート：元の表をそのまま見せ、読み取った所と未解決のセルを示す。写真のシートでは上に「! Claude に渡してよいか、あなたの許しを待っています」と「渡す」（人だけ）。読んだ格子は画像と並べて確かめる。
- 横の板「決まっていない所 n / 署名 n / コメント n」（Wire、2026-11-04）：決まっていない所（取り込みの質問）を先頭に置く。n が 0 なら、その切り替えを出さない。
  - 決まっていない所：同じ書き方の行をまとめた質問 1 つ、既定の答えに「- 既定」、行の数、ラジオ、「決める」。下に「Claude につないでいるときは、会話で答えても同じです。」下の帯の止め札「決まっていない所が n」を押すと、この切り替えになり、資料のシートの該当のセルへ跳ぶ。
- 横の板の署名とコメント：署名は版の中身のハッシュ（4 文字 × 2 組を 4 つ）、使った読み方（下書きは朱の「- 下書き」）、結び目の鎖（確定・編集・承認。✓ は確かめた、朱は待っている）。コメントは ①② の行・文・呼び名・時刻と、書く欄。
- 下の帯（立場で変わる）：編集の番の人は、左に止める理由、右に主ボタン「署名して渡す」。承認を頼まれた人は「理由を添えて差し戻す」（副）と「承認して署名する」（主）。編集の番でない人は見ることとコメントだけ。
- Claude に話す：「押込送風機の更新は、来年度の計画に入れて」

### 3.3 MERGE の白紙（新しい施設）　絵：MergeNew.dc.html

- 施設の欄（パック・施設の名前・年度の始まり・架空か）は白紙の欄に置き、版ができたあとは、見出しの施設の名前の横の文字のリンク「施設の設定」から開く。
- 計画を作るのは副のボタン：白紙では「第 1 版をつくる」、版があるときは「資料を重ねて第 n 版をつくる」。決まっていない所が 0 になるまで押せず、理由を横に出す（Wire、2026-11-04）。

- 見出しは「新しい施設」。欄は施設の名前、パック、元の版（白紙なら「なし（白紙から）」、派生なら「B 町 第 3 版」）。
- シートのタブは「＋ 資料を足す」だけ。下に大きな落とし場所。
- 下の帯「資料を落とすと、Claude がまとめて第 1 版をつくります。」主ボタンは押せない（理由を横に出す）。

### 3.4 署名して渡す（ダイアログ）　絵：Handoff.dc.html

- 題は「第 7 版に署名して渡す」。頼むこと（編集を頼む / 承認を頼む / 渡さずに自分で確定する）、宛先（メール）、ひとこと、合言葉。
- 「リンクが運ぶもの」：版の場所とハッシュ。中身は運ばない。
- ボタン：「戻る」「自分のメーラーで開く」（副）、「署名して送る」（主）。署名は人が合言葉でし、そのあと Claude が連携したメールから送る（決まり 1 の例外の 1 つめ）。
- §2.9 の確定のダイアログの中身（差分の要約、空を通さない一言の理由）を、このダイアログの上に入れる。

### 3.5 EXPORT　絵：Export.dc.html

- 確定した版から Excel を落とす。差分レポートも副のボタンで落とす。
- 書き出しは、EXPORT の画面で人が押したときだけ。Claude のツールは作らない（運営者の決定、2026-11-04、Wire のチャットで）。
- 様式に写す（「別の様式を落とす」、列の上の「← 項目」、写すものが未定の列）は P2。

### 3.6 SHARE　絵：Share.dc.html

- 今の検問所の中身は変えない（相手から見たあなた、出ていくもの、合言葉と送る）。
- 足すもの：出す先「自社の輪 / 公開の台帳」、出元の欄（鍵の指紋と「束 3 ← 束 2 ← 束 1」、名前は出ない）、主ボタン「署名して自社の輪へ出す」か「署名して公開の台帳へ出す」。
- 受け取り箱は、この画面の下の節「受け取った束」に移す。

### 3.7 設定

- 置き場所は「保管先」1 つ。版・署名・コメント・読み方を、すべてその下に置く。
- 同期フォルダの知らせ、輪のフォルダと鍵、台帳の clone の場所、自分の呼び名。
- 業種・AI に渡るもの・採点は、ここからのリンクにする。ヘッダのタブにしない。

## 4. Wire が補った所

1. 検査を MERGE のシートにした。
2. 人が受けていない決定を MERGE のシート「決定」にし、確定の止め札にした（§2.9）。
3. 渡さずに自分で確定する道（承認者のいない施設）。
4. 写真の許しを、写真のシートの上に置いた（人だけ）。
5. 橋渡しが切れたとき：署名・渡す・承認・落とす・出すは押せない。理由「橋渡しとつながっていないので押せません」を横に出す。見ることはできる。
6. 2 人が同時に書こうとしたとき：編集の番は 1 人だけ。編集を始めた版より新しい版が保管先にあれば、上に「保管先に新しい版（第 8 版、[呼び名]）があります。開き直すと、その版に重ねます。」を出し、署名を止める。
7. 差し戻し：一言の理由を必須にする。もやいに結び目「差し戻し」を足し、編集の番を前の人に戻す。
8. 受け取る側：リンクを開くと、MERGE がその版を保管先から読み、署名を確かめてから見せる。確かめられなければ、何が合わないか（ハッシュ・署名・場所）を 2 文で出し、版は開かない。
9. 未承認の読み方：承認の署名で一緒に承認される。下の帯に数を出す。
10. 色：今の検査の画面の teal / red をやめる。
11. 幅：主の面の最小幅は 1024px。表は面の中で横に送る。電話機の形は作らない。
12. タブを閉じる前の知らせ（§2.9）は、そのまま。

## 5. 作る順（運営者が 2026-11-04 に決めた）

- **P0**（動画の縦の 1 本に要る）
  - ヘッダの段のタブ。
  - MERGE の骨（シートのタブ。前の取り込み・星取表・検査をシートとして入れる）。
  - シート「決定」と確定の止め札。
  - 署名のダイアログは「渡さずに自分で確定する」だけ：題「第 n 版に署名して確定する」、欄は差分の要約・一言の理由（空は通さない）・合言葉、主ボタン「署名して確定する」。MERGE の下の帯の主ボタンは「署名して確定する…」で、このダイアログを開く。頼むことのラジオ・宛先・リンクの箱は P1 で足す。
  - EXPORT の主ボタン「Excel を落とす」（確定した版から今の様式）、副「差分レポートを落とす」。様式の名前を 1 行（「人が見る様式（MOYAI の標準）」）と中身の見本。
  - SHARE への改名。
- **P1**：トップのもやいの星取表（1 施設からでよい。派生の線は版に derivedFrom があるときだけ）、横の板の署名、読み方のシート、渡すダイアログ（編集を頼む・承認を頼む）とメール。
- **P2**（間に合わなければ「未実装」と書く）：コメント、リンクを開いて受け取る側の流れ、似た施設を重ねる、印のメニューから派生する入口、様式に写す。

## 6. データの側に要るもの

- 版：番号、親の版のハッシュ（同じ施設）、derivedFrom（ほかの施設の版。無ければ null）、署名の列（役目＝確定・編集・承認・差し戻し、呼び名、時刻、鍵の指紋）、使った読み方。
- 編集の番：施設ごとに、いま誰か。
- コメント：版・行・呼び名・時刻・文。保管先に置く。
- トップの一覧：保管先の施設と版を、月ごとに数えて返すもの。
