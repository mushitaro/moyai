## 4. 効いたこと・効かなかったこと

**効いたこと**

- **フックと deny の二重**。AI に人だけの操作を越えさせない守りを、作る側が最初に自分に掛けた。越えるための回り道を探す場面が無かった。
- **監査の自動化**。人が気づかなかった「CI が赤」を最初の回で見つけた。自分の誤りも見つけた（公開の文書から伏せたフォルダ名を、フックの試験の例に入れ直していた）。
- **Managed Agents で閉じた仕事を任せる**。試しは上限（$10〜20）よりずっと安く速かった。パッチを自分で読み、この PC で試験してから取り込む形で、7 件とも取り込めた。
- **ハッシュを先に出す見ていない様式**。書き手が生成器を見ていないことの証拠が、時刻とハッシュで残る。
- **報告を 5 つに分ける日誌**。「画面で動いた：未確認」と書き続けたので、試験が緑でも動いたとは言わずに済んだ。
- **worktree の並行**。筋 A（MCP の道）と筋 B（人だけの道）は衝突なしで統合できた。

**効かなかったこと**

- **読み手のコードを足すだけ**。見ていない様式は 3 回とも、新しい書き手が新しい書き方を持ってきた。台帳は 3 回目で未解決 0 まで読めたが、星取表・日報・報告書は回ごとに詰まり、heldout-3 は計画を作れず ⑥ は 0/142 のまま。枝の記録（日誌 11-05）では heldout-4 も、会話で 3 回詰めても計画を作れず ⑥ は 0/501。製品の答えを、会話で決めて Skill に残す 3 段にした（plan §2.17）。
- **Managed Agents の結果をそのまま信じること**。サンドボックスは Linux・Python 3.11。工場 v1 は、そこで通っても Windows で試験が 2 つ落ちた。この PC のサブエージェントに直させた。
- **監査の費用**。大きな差分ほど高く、1 日で $12。配分で止まった間、12 回続けて差分を見ていない。PM が配分を直して再開した。軽い指摘まで push ごとに直すと遅くなった。
- **サブエージェントが答える役**。計画どおりにならず、台本が答えた。

**私の誤り**（日誌の「私の誤り」から）

- 他のエージェントが同じツリーで作業中に `git add -A` を使い、作業中のファイルを一緒にコミットした（11-03、`b731036`）。今は名指しで add する。
- 試験の出力の末尾やパイプの終わりだけを見て、終了コードを見なかった。national の試験の失敗を見落として push した（11-03）。Playwright の 2 件が落ちたまま push した（`5e2d008`）。`;` でつないで落ちたまま push した（`e6b94f4` で直した）。CI が `a777145` から赤だったのに、「node:test 140」と報告した（`cc02768` で直した）。今は終了コードを直接見て、push は試験の `&&` のあとだけ。
- 公開の文書から伏せたフォルダ名を、試験の例に入れ直した（監査が指摘）。
- 「手引きの PDF は文字の層が化ける」と決めつけた。化けたのは `python -I` で表示が cp932 になったためだった。写真の「列が 1 行ずれている」も、傾きの加工による見誤りだった。
- 見ていない様式の AI を入れた回の記録を、組のフォルダの直下に置いて、組のハッシュの試験を落としたまま push した（`b8cc804` で直した）。
- 動画の 30 秒版を、設計書と計画（§5.4・§6.3）を読まずに作り、計画に書いてあることを運営者に聞いた。今は聞く前に計画を読む。
- 手元の監査の結果ファイルを誤ってコミットし、その回の費用を打ち消す行（−$0.84 を 2 回）を台帳に足した。台帳は書き換えず、足すだけにしてある。
