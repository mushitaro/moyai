# 自律の開発の回し方

2026-11-10 から、開発の統括は自律のセッション（Claude Code）がする。決まりは `AGENTS.md`、運営者に聞くことは `docs/pm.md` §4、順は `docs/roadmap.md`。
この文書は、その回し方だけを書く。

## 1. 課題の台帳は GitHub Issues の 1 つ

- 見つけた課題は Issue にする。日誌・README の「未完」・CI の監査の指摘・物差しの退行・利用者のフィードバックは、どれも Issue に写してから手を付ける。
- ラベル：柱（`area:import`・`area:ledger`・`area:skill-loop`・`area:ux`・`area:ops`）、順位（`P0`・`P1`・`P2`）、`needs:operator`（運営者の判断か操作を待つ）、`epic`（柱の親）。
- Issue には、測った値・再現の手順・終わったと言える条件を書く。行の値・キー・実在の施設の名前を書かない（公開のリポジトリ）。
- 調べた結果は Issue に書き、同じ調査を二度しない。

## 2. 順位の決め方

1. `P0`：データを壊す・人だけの操作を越えられる・main の CI が赤。
2. `P1`：`docs/roadmap.md` の柱の「終わったと言える条件」に直に効くもの。
3. `P2`：そのほか。
- 同じ順位の中は、ほかを止めているもの → 測れるもの → 小さいもの、の順。
- `needs:operator` は待たずに、ほかを進める。答えが来たら順位を付け直す。

## 3. 1 回の回し

1. **見つける**：開いた PR の CI とレビュー、main の監査の要約、物差しの表（`eval/bench/`）、新しい Issue、前の日誌の「次の一手」。
2. **選ぶ**：§2 の順で、並べて進められるものを 2 本まで。
3. **作る**：送る側と受ける側を同じ変更で。物差しに効く変更は、まず `--only` で絞って測り、最後に全部を測って `eval/bench/` を入れ直す。
4. **試す**：`npm run typecheck`・`npm test`・`npm run check-publish`。画面を変えたら関係する e2e。全部の試験は push の前に 1 回。
5. **見直す**：作った役とは別の役が、差分だけを見る（守りに関わる変更・取り込みの層・共有の芯は必ず）。指摘は直すか、直さない理由を PR に書く。
6. **PR**：下書きで出す。型（`.github/pull_request_template.md`）の 5 つの分け方で報告し、閉じる Issue を書く。
7. **残す**：`docs/progress/<日付>.md` に、したこと・5 つの分け方・使用量・次の一手。

## 4. 自動の検査

- `ci`：ビルド・型・試験・公開の前の検査（ubuntu と windows）。
- `ci` の `pack-bench`：物差しを測り、記録した表（`eval/bench/`）と比べる。数が 1 つでも違えば落ちる（退行はもちろん、良くなったのに表を入れ直していないときも）。
- `audit`：main への push の差分を、決まりに照らして読む（書き込まない）。
- `ledger-validate`：台帳の PR を、アプリと同じ関数で確かめる。
- 判定はコードがする。AI に合否を決めさせない。

## 5. 使用量の使い方

- 調べもの（どこに何があるか）は下位か中位のモデルの調査役に渡し、主線は結論だけを受ける。
- 仕様の閉じた実装（画面の直し・受け口の直し・試験の追加）は、作業ツリーを分けた作業役に渡す。主線は差分を読んでから取り込む。
- 取り込みの層・共有の芯・人だけの操作に関わる所は、主線（上位のモデル）が自分で読む。
- 並行は 2 本まで。多人数のワークフローは、凍結の前の見直しにだけ使う（`docs/plan.md` §3）。
- API のキーを使う仕事（`moyai eval`・開発のエージェント・監査）は、`config/models.json` の配分の中だけ。配分を変えるのは運営者。
- モデルの名前は、この文書にも Issue にも PR にも書かない（`config/models.json` だけ）。

## 6. 運営者に聞くこと

`docs/pm.md` §4 に加えて：公開（配置・公開の台帳に本物を受ける）、権利（第三者の資料・商標・ライセンス）、費用（API の配分・有料のサービス・決まった時刻の自動の回し）、画面の約束と共有で出す欄の変更。
聞くときは、選べる道・それぞれで起きること・推す道と理由を添えて 1 回で聞く。答えを待つ間は、ほかを進める。

## 7. しないこと

- `AGENTS.md` の「決めるのは人」の操作（確定・送信・昇格・鍵・マージで載せること）。
- 落ちる試験を飛ばす・消す・緩めること。測っていない数を書くこと。
- 提出の版（タグ `submission`・枝 `hackathon-release`）に触れること。
