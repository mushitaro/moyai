# MOYAI の守り

このファイルは `src/shared/security.ts` が、ツール定義と経路の許可の一覧から作ります。手で直さないでください（`MOYAI_WRITE_DOCS=1 npx vitest run tests/contract/security-doc.test.ts` で作り直します）。

決めるのは人です。確定・送る・昇格・保存は、AI のツールにありません。AI クライアントが使えるのは下の表のツールだけで、人だけの操作は作業画面のボタンと、端末の人だけのコマンドにあります。

例外は 2 つです（MCP の instructions の安全の決まり 1 と同じ）。どちらも、承認は人の署名です。

1. 引き渡しのメールを送ること。人が HOSHITORI で「署名して渡す」を押すと、`intake_survey` の handoff に MOYAI が用意したメールの文（宛先・件名・本文）が入ります。利用者が送ってと言ったら、Claude が利用者の連携したメールから、その文のまま送ります。中身は版の場所とハッシュと、リンクの中の使い捨ての合言葉（受け取りに使う）です。合言葉は、文を読んだ AI の提供者にも渡ります。受け取れるのは最初の 1 回だけです。計画の中身は運びません。MOYAI にメールを送るツールはありません。
2. 未承認のルール（読み方と計画の規則）の下書きを保管先に書くこと（`reading_skill_register`）。保管先の決まった場所に、未承認の 3 段目の Skill として書きます。書けるのは未承認の下書きの場所だけで、消去・範囲の変更はしません（承認済みの中身はハッシュのまま versions/ に残り、当て続けられる。今の下書きのファイルは書き直すことがある。範囲は置き場所で決まる）。承認は、そのルールを使った版への人の署名です。計画の規則は、その版で人が受けた周期の案のもとになったものだけを、版の記録に載せます。

施設ごとの作業中を保管先に書くのは、AI ではなく作業画面の作業の写しです（下の「上限」の節）。

## 上限

- 星取表の行は、1 回 200 行まで、会話（中継の 1 つの接続）で 2,000 行まで。数えるのは橋渡しで、タブを読み込み直しても数は戻りません。
- 要約の欄ごとの多い値は 20 まで、文字は 60 字まで。行の参照の例は 10 件まで。
- 資料は 1 ファイル 64 MB まで（作業画面のタブのメモリに読みます）。
- 施設ごとの作業中（mushitaro/moyai#82）：資料の写し・資料の印・取り込みの答え・作業中の計画・確定のシートの確定を、閉じても資料ごと戻せるよう、変わるたびに間を置いてまとめて保管先に書きます。書くのは橋渡しで、作業画面だけの経路（`/tab/work-source`・`/tab/work-save`。タブの秘密で確かめ、人だけの経路ではない）から受けたものだけです。書く場所は `plans/<計画ID>/work/state.json` と、資料のバイト列の `plans/<計画ID>/sources/<SHA-256>`（版の資料と同じ所。同じ中身は 1 つ）。作業中は版ではなく、署名も鎖もありません。AI のツールと中継には、作業中を読む・書く・消す道がありません（ツールで作業画面が変わった結果が、作業画面から書かれるだけ）。消すのは人だけ（トップの「作業中」→「作業中を消す」。人だけの経路 `work_discard`）で、作業中と、作業中だけが持っていた資料の写しを消します（署名した版と版の資料は消しません）。写真も資料として写します（写真の読み取りの格子は写さないので、戻した写真は読み直しが要る状態で並びます）。作業画面だけの経路はタブの秘密で確かめるので、同じ作業画面（127.0.0.1 の同じ出どころ）で動くものは、保管先の作業中を読めます。ほかのタブの作業中（確定していない変更か未確定がある）は、人が戻すか消すまで上書きしません。作業画面のブラウザの保存領域（IndexedDB）には、作業を写しません。Service Worker がブラウザに覚えるのは画面の殻（index.html・JS・CSS・書体）だけで、人だけの経路とツールの道は覚えません。
- `intake_add_files` は、Skillパックの demo/ の架空の資料か、利用者がチャットで言ったフォルダの直下の .xlsx・.xls・.csv・.pdf・.jpg・.png だけを、1 回 200 個まで、1 つ 64 MB まで読みます。状態フォルダとリポジトリの中・`..` を含む道・シンボリックリンクは読みません。中身は橋渡しが資料ごとのワンタイムトークンで作業画面のタブに渡し、AI に返すのは名前・大きさ・件数（シートと行の数）・断った理由だけです。ほかの種類のファイルと下のフォルダは、名前を返さずに数だけを返します。`source: template`（利用者が言った様式の .xlsx 1 つ、8 MB まで。道の確かめは同じ）は、作業画面の出力の様式の欄に入れるだけで保存しません。AI には様式の形（シートの名前、字のあるセルの位置と字、結合、式の位置と年度の参照の式）と計画の階層の名前を返します。値の入ったデータの行は、字も値も返さずに範囲と数だけを返します。
- 写真は、人が作業画面で 1 枚ずつ許したものだけを、1 回に 1 枚渡します。作業画面が長辺 1,568〜2,000 px・JPEG で約 100 KB 以下に描き直し（切り抜かず、位置などの付け足しの情報は落とす）、橋渡しは、許した画像のハッシュと合うものだけを渡します（300 KB を越えるものは渡しません）。許しは 1 回渡すと使い終わります。
- `screen_set` は作業画面の見せ方（明暗・開く画面・星取表の階層の並び・機器の並び・計画の最大年度）だけを変えます。見せ方は施設ごとにブラウザに覚え、作業中の計画と版の記録には入れません。保存先は変えません。橋渡しが設定と同じ確かめ（絶対の道）を通した道を、設定の画面の保存先の欄に入れて開くだけで、保存は人が押します。答えには今の保存先の道を添えます。`templateLayout`（様式の写し方の案）は、作業画面が様式に照らして下書きとして置くだけです。答えは書いたときの数（行・年度・数えた明細）で、金額などの値は返しません。写し方と様式の保存と出力は、人が出力の画面で見本を見て「署名して出力」を押したときだけです。
- `share_preview` は、SHARE の画面と同じ関数で作った共有ファイルの、形と数（共有先の種類・版の番号と年度とハッシュの頭・写る機器と作業と作業の年度の値の数・伏せる欄・同区分の施設の数・塊の数）だけを返します。機器・作業・施設の名前、年度、階級、分類のコード、費用と、共有ファイルのバイト列は返しません。施設の札（見え方の 1 行）は、軸のコードの名前で返します。作業画面を SHARE に切り替えます。Claude が会話で聞いた見え方の答え（`answers`。施設の答えがある軸には効かない）と共有先（`dest`）は、そのタブの SHARE の画面の今の選びになるだけで（画面に「Claude の入力」と出る）、署名・送る・設定はしません。署名して送るのは、人が SHARE の主ボタンを押したときだけです。
- 外へ出た台帳：橋渡しは、AI に返した結果ごとに、ツールの名前・大きさ（バイト）・行の数・添えた画像の大きさを、橋渡しのメモリに新しい 2,000 行まで持ち、会話ごとの合計も持ちます。返した中身は持ちません。ファイルには書かず、橋渡しを止めると消えます（画面に出すのは未実装）。

## 人だけの操作（AI のツールに無い）

次の経路は、タブの秘密（作業画面のタブが作り、HTML にもどの GET にも入れない）と、ワンタイムトークン（操作と中身のハッシュに結び、120 秒で切れ、1 回使うと消える）の両方を求めます。一覧に無い経路は断ります。

| `POST /human/readings-read` | `readings_read` | 保管先の承認済みの読み方（3 段目の Skill）を、作業画面に読み込む |
| `POST /human/readings-lineage` | `readings_lineage` | ルールの詳細の適用先：保管先の版の記録から、ルールの版を載せた版（施設・版・時刻・編集の番）とルールの置き場所を読む（読むだけ） |
| `POST /human/reading-feedback-save` | `reading_feedback_save` | 読み方のフィードバックを書き出す：画面が全文を見せたルールの形と数（moyai.reading-feedback/0）を、形と固有名詞の網 2 で確かめ直してから、保管先の feedback/ に置く（送らない。送るのは人） |
| `POST /human/peers-compare` | `peers_compare` | 受け手：立場ごとに、台帳の clone と自分の共有フォルダの ✓ の共有ファイルから、類似施設の行と統計の行を作る |
| `POST /human/photo-allow` | `photo_allow` | 写真を 1 枚、AI クライアントに渡すことを許す（渡す画像のハッシュに結ぶ。1 回渡すと使い終わる） |

人だけの操作の名前は 45 個です。ツールの名前と重ならないことを試験で確かめています。

## 作業画面だけが呼ぶ経路と、中継の経路

作業画面だけが呼ぶ経路は、Origin・Sec-Fetch-Site とタブの秘密を求めます（人だけの操作ではないので、ワンタイムトークンは求めません）。中継の経路は、状態フォルダの鍵ファイルの鍵を求め、ブラウザからの要求（Origin・Sec-Fetch-Site のあるもの）を断ります。

| 経路 | 求めるもの | 説明 |
|---|---|---|
| `POST /relay/tool` | 鍵ファイルの鍵 | 中継からのツールの呼び出し |
| `POST /relay/stop` | 鍵ファイルの鍵 | 橋渡しを止める（moyai uninstall と、古い版の橋渡しを替える中継が、鍵ファイルの鍵を添えて送る） |
| `POST /tab/intake-file` | タブの秘密 | AI が intake_add_files で入れる資料の中身を、作業画面が 1 つずつ取りに来る（橋渡しが資料ごとに渡したワンタイムトークンと、そのタブの回だけ） |
| `POST /tab/window-arrange` | タブの秘密 | ヘッダの「Claude と並べる」：Windows で、Claude Desktop の窓を左、MOYAI の窓（押した直後の前面の窓）を右に並べる（体は無し。PowerShell の決まった台本だけを走らせ、利用者の値を渡さない） |
| `POST /tab/work-source` | タブの秘密 | 作業中の資料を 1 つ、保管先の計画のフォルダに中身のアドレス（SHA-256）で置く（版の資料と同じ所。同じ中身は 1 つ） |
| `POST /tab/work-save` | タブの秘密 | 施設の作業中（資料の印・取り込みの答え・作業中の計画・確定のシートの確定）を、保管先の plans/<計画ID>/work/state.json に書く（変わるたびに間を置いてまとめて。資料の写しがそろっているときだけ） |
| `POST /tab/work-list` | タブの秘密 | 保管先の作業中の一覧（トップの行の「作業中　未確定 n」。名前・未確定の数・時刻だけ） |
| `POST /tab/work-read` | タブの秘密 | 施設の作業中を読む（トップの「作業中」を押したとき、資料ごと続きから開く）。資料は sha256 を添えると 1 つずつバイト列で返す |

## 網の外側

- 橋渡しは 127.0.0.1 の 1 つのポートだけで待ち受け、Host・Origin・Sec-Fetch-Site を確かめます。これは Web ページからの呼び出しへの守りで、同じ PC の同じ利用者のプロセスは止めきれません（curl も Node も Origin を偽れます）。
- 中継と橋渡しの間は、状態フォルダの鍵ファイル（利用者だけが読める既定の権限）で確かめます。同じ利用者のプロセスには読めます。
- シェルを持つ AI（Claude Code）には、リポジトリの `.claude/settings.json` の deny と PreToolUse のフック（`scripts/guard-hook.mjs`）の二重で、127.0.0.1 への HTTP・状態フォルダの読み取り・保管先の計画のフォルダの施設の署名鍵（share/keys/）の読み書き・輪のフォルダへの書き込み・人だけのコマンド・見張りのフックと `.claude/settings.json`・`.claude/settings.local.json` の書き換えを止めます。悪意のある同じ利用者のプロセスは止めきれません。
- 通信の例外は公開の台帳と、最新の確かめです。GitHub の道は、行き先が github.com と api.github.com だけです。
- 最新の確かめ（運営者の決定 2026-11-11。mushitaro/moyai#65）：入っている MOYAI（`moyai setup` が版ごとのフォルダに入れたもの）の橋渡しは、起動のときと動いている間 6 時間ごとに、github.com の mushitaro/moyai の main を git で取得して新しい版があるかを確かめ、あれば別のフォルダで用意します（切り替えは次の起動）。送るのは git の問い合わせだけで、施設・行・鍵・設定の中身は送りません。取ってくる先は固定で、ツールの引数では変えられません。設定の「最新の確かめ」を「しない」にすると、一切問い合わせません。開発の clone（`setup --dev`）では動きません。
- 公開の台帳は、台帳だけを置く別のリポジトリ（mushitaro/moyai-ledger。置き場所の設定は `config/ledger.json`）です（2026-11-12 に MOYAI のリポジトリの `ledger/` から切り替えた。運営者の決定 2026-11-10。mushitaro/moyai#20）。GitHub の道は台帳のリポジトリをフォークして PR を出します。台帳の PR の検証（台帳のリポジトリの `ledger-validate`）は、MOYAI と同じ関数（`moyai ledger validate-pr`）で、共有ファイルと取り下げの印の追加のほかの変更を ✗ にします。
- MOYAI 経由の道（運営者の決定 2026-11-07）は、行き先が公開の台帳の受け口の 1 つだけです。送るのは、公開の台帳に載せるのと同じ共有ファイル（と、その鍵自身の署名の失効記録）だけです。受け口は送り手の IP を数えるのに使い、残しません。受け口が運営者（tsunagi）の GitHub のアカウントで PR を出します。受け口のトークンは台帳のリポジトリ（mushitaro/moyai-ledger）だけの Contents と Pull requests に絞るので、MOYAI のコードには書けません。
- 鍵と GitHub のトークンは合言葉で包みません（運営者の決定 2026-11-04）。人の鍵とトークンは同期されない状態フォルダに、束に署名する施設の鍵は保管先の計画のフォルダ（share/keys/）に置きます。MCP のどのツールの結果にも、鍵とトークンの中身は入れません。
- 人だけのコマンド（鍵を作る、送る、台帳に出す）は、標準入力が端末でなければ断ります。
- `moyai setup`（AI クライアントにつなぐ・送信者の名前）と `moyai uninstall`（消す）は、何をどこに書くか・消すかを先に出し、`--yes` が無ければ端末で「はい」をもらいます。`--yes` は、利用者がチャットで確かめたあとに Claude が付けます（運営者の決定 11-06「チャットだけで入れる・デモする・消す」）。保存先（計画の版）を消すのは `--remove-root` のときだけです。
- API のキーを読むのは、Skill の採点の CLI（`moyai eval`、`src/eval/`）だけで、環境変数 `ANTHROPIC_API_KEY` から読みます。写真の読み取りと MCP のツールはキーを読みません。チャットでもツールでもキーを受け取らず、値を画面・記録・ログに出しません。

## 保証できないこと

1. 1 回の上限は、繰り返し呼べば越えられます（だから会話の合計に上限を置き、外へ出た台帳で会話ごとの合計を数えます。合計は橋渡しを止めると消えます）。
2. チャットに Excel を添付すれば、ファイル全体が AI の提供者に渡ります。
3. ファイルを読める AI は、確定した計画のファイルを直接読めます。
4. Documents が同期フォルダ（OneDrive など）の下なら、確定した計画は会社のクラウドに上がります（だから最初に調べて知らせます）。
5. 「外へは送らない」はアプリの通信の話で、データの行き先の保証ではありません（例外は、上の公開の台帳と最新の確かめ）。
6. 写真とスキャンの読み取りでは、人が許したその画像が AI の提供者に渡ります。
7. 画面を操作できる AI の道具（ブラウザやデスクトップの操作）は、人だけのボタンを押せます。作業のある作業画面が開いているとき、あとから開いたタブは橋渡しに断られますが、AI の道具が前のタブそのものを操作するのは止めきれません。
8. 計画のフォルダを読める人と AI は、施設の署名鍵を写せます（写した人は、その施設として束を出せます）。保管先が同期フォルダなら、施設の署名鍵も会社のクラウドに上がります。
9. シェルを持つ AI は、見張りのフックを越えられます（スクリプトを書いて走らせる・差分のファイルを git apply する・git reset や git checkout で枝ごと戻す・道に ./ を挟んだシェルの書き込み）。フックが見るのは、AI の道具の呼び出しの字だけです。
10. 施設の署名鍵のファイルを失くすと、その鍵の失効の記録に署名できません。受け手はその鍵を数え続けるので、再発行した新しい鍵が照合されると、同じ施設を 2 つに数えます（長く出していないメンバーを数えから外す決まりは、まだありません）。
11. 費用のセルを AI の見本で伏せるのは、取り込みが費用の列と見分けた列（括弧の外の見出しが「費用」「金額」「工事費」「修繕費」「予定価格」「支払額」「契約額」「請負額」「見積額」「概算額」で始まるか終わるもの。例「概算費用」「契約金額」）だけです。ほかの言い方の見出し（「見込額」「予算額」「単価」など）の列の値は、見本にそのまま出ることがあります。
12. `intake_add_files` のフォルダが、利用者がチャットで言ったものかを、橋渡しは確かめられません。AI が別のフォルダ（状態フォルダとリポジトリの外）を指せば、その直下の資料が作業画面に入り、要約の見本として AI に渡ります。作業画面の作業の一覧に、AI が資料を入れたことが出ます。
13. 公開台帳に載せた束は、今は画面から取り下げられない（印の形は決めた）。失効記録（台帳の `ledger/bundles/<鍵ID>/retired.json`、その鍵自身の署名）は、CLI の `ledger submit` か受け口に送れば受けますが、作る画面のボタンはまだありません。取り下げても、載った束のファイルは消えず、受け取った人の複製も残ります。
