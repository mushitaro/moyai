# MOYAI のデータの名前

利用者が画面で見て、Claude が資料を当てるデータの名前を 1 行ずつ決める表。2026-11-06 に Wire の頼みで作った（運営者「データの名前の意味を決めないと、Claude が資料を正しいデータに当てられない」）。運営者の決定（同日）：名前の表は案でなく作るもの。図と Skill の両方から引く。

- 運営者の定義は `docs/words.md`・`docs/screens.md` 3.8・3.9・`docs/plan.md` §2.4 と、運営者の 11-06 の直しから取った。運営者が決めていないものは「未定義（案）」とし、案の定義を書いた。案は運営者の確認まで決まりではない。
- 画面の言葉は `docs/words.md` と `src/app/text/`、コードの欄は `src/shared/plan.ts`（計画の型）から取った。`src/shared/fields.ts` とずれる所は「食い違い」に書いた。
- 資料の手本は、しらかば野（`samples/waste-incineration/shirakabano/files/`）の 6 種の資料：星取表・作業日報・工程表・発注台帳・完成図書（第3編 機器仕様一覧表）・日常点検表（写真）。中身は `docs/sample-making.md` と施設の README による。
- 「当ててはいけない例」は、Claude が資料を読むときに起こしやすい読み違い。業種によらないものと、業種の語が入るもの（パック）を続けて書いた。
- 1〜4 章の表は `src/shared/data-names.ts`（名前・定義・画面の言葉・欄・業種によらない当ててはいけない例）と `packs/waste-incineration/data-names.json`（資料の手本・業種の当ててはいけない例）から作る。表を直すときはそちらを直し、`MOYAI_WRITE_DOCS=1 npx vitest run tests/contract/data-names.test.ts` で書き直す。5 章・6 章は手で書く。
- 同じデータから、1 段目の Skill（`skills/moyai/SKILL.md`）の「データの名前」と、パックの Skill（`packs/waste-incineration/SKILL.md`）の「資料とデータの名前」を作る。Claude には intake_survey（part: skills）で届く。
