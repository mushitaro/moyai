# 【架空】デモの輪（7 拠点）

架空の 7 拠点が 1 つの輪に束を出した姿です（`docs/plan.md` §2.8「デモの輪は 7 拠点」）。拠点も施設も、どれも架空です。

```
node dist/cli.js verify demo-ring
```

で、輪の決まり・仲間・束を、受け手（`moyai verify ring` と作業画面の SHARE）と同じ関数で確かめます。全員 ✓、わざと入れた ✗ の束が約束の理由で ✗ なら、終了コードは 0 です。

## 中身

- `<輪ID>/circle.json`：輪の決まり（コードの決まり。拠点 01 の鍵で署名）
- `<輪ID>/members/<鍵ID>.json`：仲間の公開鍵（本人が署名。表示名は置かない）
- `<輪ID>/bundles/<鍵ID>/<連番>-<ハッシュ先頭16>.json`：束
- `demo-ring.json`：確かめの約束。確認済みに数える鍵（拠点 7 と、わざと外れた束を置いた 1）と、✗ になるはずの行と理由

## 作り方

`node scripts/demo-ring/build.mjs` が作りました。公開の台帳のデモの 10 施設と同じ正解の世界（`samples/truth/waste-incineration/ledger-01`〜`07`。工場の `samples/factory/ledger_worlds.py` が組む）から、取り込みを通さずに計画を直接書き、MOYAI の本物の写し取り・数え直し・署名（`src/share/` の `previewBundle`・`sealBundle`）で、1 拠点 1 束にしました。1 つの束は 1 つの世界だけから作り、施設をまたいで混ぜていません。拠点は 1 つずつ送り、送る前に受け手と同じ関数で、それまでの仲間の束を読んでいます（6 つめと 7 つめの拠点は仲間が 5 以上になるので、輪だけに出す `UPGRADE` の塊が入ります）。

わざと外れた束は 1 つです。8 つめの鍵（`ledger-08` の世界）が、本物の封で作った束の塊に費用の欄を足し、本物の署名の関数で署名し直しました。署名・道・連番・鎖は正しく、外れは中身だけです。受け手は「形の外れ・金額の形・自由記述」の理由で ✗ にします。

## 秘密鍵

秘密鍵はこのリポジトリにありません。道具は走らせるたびに鍵を作り、秘密鍵と「どの拠点がどの世界か」の対応は、一時の状態のフォルダ（`--state` か OS の一時フォルダの `moyai-demo-ring-*`）にだけ書きます。作り直すときは、`demo-ring/<輪ID>/` と `demo-ring.json` を人が消してから道具を走らせます（鍵が変わるので、輪 ID もすべての束も変わります）。

## 確認済みの鍵について

本物の輪では、仲間の鍵は指紋を電話で読み合わせてから「確認済み」になり、それまでは k に数えず ✗ にします。デモでは読み合わせる相手がいないので、`verify demo-ring` は `demo-ring.json` の鍵を確認済みに数えます（あなたの状態フォルダは読みません）。`moyai verify ring demo-ring` で確かめると、読み合わせていない仲間はすべて「未確認」の ✗ になります。

改行の変換を受けないよう、`.gitattributes` で `demo-ring/**` を `-text` にしています（Windows の autocrlf で束のバイト列が変わると、署名とハッシュが ✗ になるため）。
