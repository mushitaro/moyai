# 資料を 85 個まとめて入れても、読めて、Claude に届く

見ていないサンプル（ある施設の資料 85 個：Excel 1・CSV 12・PDF 72）を入れた測りで、4 つの穴が出た（2026-11-07 朝）。どれも業種によらない一般の形として直す。その施設の資料に合わせた継ぎはぎはしない（その資料はここに無い。形の説明だけを渡す）。

1. **資料を混ぜると、1 冊なら読めた Excel が読めなくなる**：中長期の計画表の Excel 1 冊だけなら、落とした直後にデータ 2,672 セル。同じ Excel を CSV・PDF と一緒に入れると、データ 0 セル・未解決 7,966（同じ質問に答えたあとも 0）。資料をまたぐ処理（`formGroups`・`link.ts` の結び・様式の判定・列の役目の質問）が、ほかの資料の形に引きずられていると見る。原因を突き止め、1 冊で読める資料は、ほかの資料と一緒でも同じに読める（同じ数のデータのセル）ようにする。これを試験で縛る（形の違う資料を足しても、ある資料の読みが変わらない）。
2. **intake_survey の答えが大きすぎる**：質問 1,170 問で答えが約 658 KB（質問の本文が 488 KB）。Claude の 1 回の結果の上限を越える。答えの大きさに上限（目安 60 KB）を置き、越えるときは質問を同じ形ごとにまとめた要約（形・件数・代表の 1 問）と、続きを読む道（part と cursor、か limit）を返す。質問の本文から重複する見本を減らす。上限を越えないことを試験で縛る。
3. **同じ列の役目を資料ごとに聞く**：同じ見出しの列を持つ CSV 12 本で、列の役目を 12 本 × 列ごとに 1 問ずつ聞き、639 問になった。見出しの並びが同じ資料（同じ様式）の同じ見出しの列は、1 問にまとめて聞き、答えは全部に当てる。
4. **CSV の 1 行目が題と抽出の条件のとき、それを見出しと読む**：例「【架空】発注明細一覧（最新状態）」「抽出日時」「基準日」の行のあとに、2 行目が列の見出し。題・条件の行（セルが少ない・「：」や日時・「一覧」などの手がかり、`packs/_cues/cues.json`）を見出しにせず、次の行を見出しにする。手がかりの語を足すのは、性質の違う 2 つ以上のファイルで質問が減ると試験で示せたときだけ（`docs/plan.md` §2.6）。
5. 「名前の欄が空」の質問の文に、どの資料のどの行かを添える（今は質問 id と行数だけ）。

先に読む：`AGENTS.md`、`docs/plan.md` §2.3・§2.6・§2.13、`src/import/session.ts`・`structure.ts`・`records.ts`・`link.ts`・`questions.ts`・`compose.ts`・`csv.ts`、`src/shared/tools.ts`（intake_survey の答えの形。字は変えず、形に足すだけ）、`samples/`（架空の資料の作り手）、`tests/heldout/`。

試験の資料は、`samples/factory/` で作る架空の資料（Excel の星取表 1・題の行のある CSV 何本か・PDF 何本か）で組む。100 個前後を入れても、答えが上限の内・止まらない・Excel の読みが 1 冊のときと同じ、を縛る。

触らないもの：署名される字（版の記録・basis・LEDGER_SOURCE ほか）、`packs/` の Skill の文、`src/app/`（画面）。MCP の instructions は 4,096 字の上限に近いので足さない。
