# 会話の繰り返しで詰めるときの、ルールと問いの穴を直す

運営者の方針（11-08）：新しい施設は、会話で作る 3 段目のルール（`src/import/reading.ts`）で詰める。測るのは、何回の会話で計画まで詰め切れるか。
試験のセッションが、見ていない施設（青葉台、資料 86 本）を会話だけで詰めた。記録は `docs/progress/conversation-loop-2026-11-08.md`。
1 回目は聞いた回数 6・ルール 48 で計画まで行き、2 回目は問いがほぼ 0 だった。そのとき、ルールと問いの仕組みに次の穴が見えた。
資料の形の読みは直さない（標準の読み手に足さない）。直すのは、ルールと問いの仕組みだけ。

## 1. 行の役割のルールが広く当たりすぎる（いちばん重い）
- 今の動き：`rowRole` は「行のどれかのセル」に当たる。prefix が true だと、そのセルの字の頭と比べる。
- 起きたこと：
  - 頁の頭書き「【架空】青葉台環境センター」を外すつもりで、prefix「【架空】」の rowRole を置いた。
  - すると、発注明細の仕入先名「【架空】東浜耐火」にも当たり、93,987 セルが外れた。
  - 発注明細の結び付き（workJoin）が 1,631 → 0 になった。答えは成功の形で返った。
- 直し：
  - prefix の rowRole は、行の最初の字のあるセル（いちばん左）だけと比べる。丸ごとの一致（prefix なし）は今のまま、どのセルでもよい。
  - reading_rules_propose の答えに、ルールごとに当たった行の数と資料の数を返す。
  - 1 つのルールが、置く前に読めていたデータのセルを 1,000 以上外すときは、答えの note に「ルール n が読めていた m セルを外した」と書く。
  - ツールの説明（`src/shared/tools.ts` の reading_rules_propose）に、rowRole の当たり方（丸ごとはどのセルでも、prefix は行の頭のセル）を 1 行で書く。

## 2. 決まった答えのルールが、問われていない資料にまで効く
- 今の動き：`answer` は、質問の kind と、質問の文に match の字を含むことで当たる。
- 起きたこと：
  - 「参考として計画に使わないか → reference」の決まった答えを置いた。問われたのは 5 本だった。
  - それが 47 本すべての同じ形の質問に効いた。
  - 質問 0・未解決 0 と返り、作ると「計画に使う資料が無い（どの資料も参考として外した 47）」になった。
- 直し：
  - 資料を丸ごと外す答え（参考として外す・資料を読まない）の answer ルールは、when.file の無いときは効かせない。そのとき、reading_rules_propose の答えの note に「資料を丸ごと外す答えは、when.file で資料を指してください」と返す。
  - ツールの説明にも 1 行書く。
  - intake_compose で「どの資料も外した」で止まるとき、止める理由に、外したルールの id を添える。

## 3. 下書きのルールを消せない
- 今の動き：reading_rules_propose で置いた下書きのルールは、抜いて置き直しても残る。
- 直し：reading_rules_propose に `remove: [ruleId]`（下書きのルールの id、50 まで）を足し、下書きから外す。
  - 承認済み（保管先の versions/）は外せない。今どおり。
  - 答えに外した id を返す。
  - 試験：外したあと読み直すと、そのルールの効きが消える。

## 4. intake_survey が重い
- 今の動き：limit 1 でも、資料の一覧（86 本）を毎回返す。
- 直し：
  - part を指定したときは、その part の中身だけを返す（files は part: all か files のときだけ）。
  - files にも limit を効かせる（既定 20、超えた数は filesTotal で返す）。
  - 出力の型と、ツールの説明を直す。

## 5. 決まった答えで、黙って入った切れ端の機器を知らせる
- 起きたこと：頁の頭書き「【架空】青葉台環境センター」が、「先の資料に無い機器は入れる」の決まった答えで、質問なしに 266 の機器の節になった。
- 直し：
  - intake_survey の compose の結果に、資料ごとの新しい機器の節の数（上位 10 資料）を足す。
  - 同じ名前の機器の節が 20 以上できた資料は、note に名前と数を書く（Claude が利用者に見せられるように）。
